Created: 2026-10-19

## 1. 背景与目标

当前项目的自动化测试会使用测试临时目录，但缺少一个可直接启动桌面程序、预置合成素材记录、收集诊断日志并在程序结束时清理测试数据的统一入口。人工走查如果直接启动应用，容易打开工作区中的数据库、设置、标签配置或结果文件。

本任务提供一个可复用的 Python 临时测试环境和一个附属的人工 GUI 测试脚本，使维护者可以在不接触生产管理数据和真实素材的情况下走查工作台、素材库、标签库、设置和数据目录相关功能。

## 2. 范围内

- 提供 `ManualTestEnvironment` 上下文管理器：创建临时数据根、合成素材目录、SQLite 数据库、设置、标签配置和结果文件。
- 临时服务实例通过显式路径注入，禁止解析项目默认数据目录。
- 提供有限数量的合成素材记录与标签数据；不调用 AI，不依赖真实视频素材。
- 为应用日志和分析任务指标配置独立的诊断目录；临时数据库、配置、结果和合成素材在会话结束时删除。
- 生成清理报告，记录临时目录是否成功删除及失败原因；诊断日志和报告保留在 Git 忽略的 `logs/manual-tests/` 下。
- 提供可见 GUI 启动脚本，支持记录数量、诊断目录和临时素材模式参数。
- 临时人工测试界面禁用管理数据目录切换入口；直接调用同一处理函数也必须早退，避免写入应用真实定位记录。
- 增加自动化测试，验证路径隔离、日志保留、清理和环境变量恢复。
- 提供简体中文人工测试使用说明和清理边界。

## 3. 范围外

- 不修改生产数据库、工作区中的 `data/`、根目录配置、真实视频或用户 API 配置。
- 不把临时测试数据复制到诊断目录；诊断目录只保存日志、分析指标和清理报告。
- 不为测试环境增加产品内的多库切换能力。
- 不自动调用外部 AI API，不生成需要提交的测试素材或构建产物。
- 不承诺在强制终止进程、系统崩溃或文件被外部程序长期占用时完成清理；清理失败必须如实记录。

## 4. 已确定方案

1. 由环境管理器使用 `tempfile.mkdtemp()` 创建会话根目录，并在 `close()`、上下文退出和 Python 正常退出钩子中尝试删除。
2. 服务通过 `db_path`、结果 JSON/CSV 显式指向会话数据根；不调用默认数据目录解析。
3. 人工脚本启动 GUI 前创建并填充环境；退出 Qt 事件循环后先请求/等待可见后台任务，再关闭服务环境，避免 Windows 文件句柄阻止删除。
4. 诊断路径默认使用 `logs/manual-tests/<session-id>/`；日志路径通过环境变量传给分析指标模块，并由脚本配置 `VideoOrganizer` 文件处理器。
5. 临时环境默认只生成文本占位媒体并直接写入合成数据库记录；可选尝试生成短视频，编码不可用时退回占位文件并记录警告。
6. 日志中不写入 API Key；人工测试如果手工填写连接信息，连接信息仍只存在临时数据根，数据根关闭时删除。

## 5. 验收标准

- [x] 从任意工作目录运行人工脚本时，服务数据库、设置、标签配置、结果和合成素材均位于会话临时根目录。
- [x] GUI 可以打开并看到预置的素材库记录与标签数据，默认不会读取项目工作区数据。
- [x] 临时会话的设置页禁用数据目录切换；直接调用处理函数也不会启动目录选择或定位记录写入。
- [x] 会话结束后临时数据库和临时素材根不存在；诊断目录仍存在且包含会话日志和清理报告。
- [x] 分析指标默认写入本次诊断目录，不写入项目根 `logs/analysis_jobs/`。
- [x] 创建失败、清理失败和后台线程未结束时不静默报告成功，清理报告记录错误。
- [x] 关闭环境重复调用安全；环境变量和日志处理器不泄漏到后续测试。
- [x] 新增自动化测试通过，且既有测试不被删除或放宽。

## 7. 风险与回滚

风险主要是 Windows 下 Qt/SQLite/后台线程仍持有文件句柄导致清理失败，以及环境变量或日志处理器影响当前 Python 进程中的后续测试。通过退出前等待、幂等清理、清理失败可重试、处理器关闭、环境变量恢复和清理报告降低风险。

回滚方式是删除新增的临时环境模块、人工脚本、测试、说明文档和本地规格；不会触碰生产数据。清理失败时保留诊断目录和失败信息，人工可按报告中的临时路径确认后删除。
