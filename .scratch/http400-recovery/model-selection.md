# 获取模型列表并选择填入

Status: claimed

GitHub Issue: #63
Branch: feat/63-http400-recovery

## 目标与范围

用户要求降低模型名配置门槛，支持拉取供应商模型列表并选择填入，同时保留任意自定义模型。统一覆盖AI引擎的档案默认模型、任务路由、400备用API及手动指定备用模型；不修改已有路由或分析请求行为。

复用已有OpenAI兼容客户端的`models.list()`以及后台IO线程；不新增密钥管理、外部服务或模型能力猜测。列表在内存中按实际连接身份隔离，仅点击获取/刷新时请求。获取只更新候选，不自动替换输入或保存配置；同连接请求去重，切换连接后忽略过期结果。未保存的Key/地址也可用于当前连接拉取，不强制保存。

## 验收与约束

- 模型可搜索选择或直接手填；读取失败/空列表/不支持接口时保留手填入口和原值。
- 列表去重排序，提取模型ID，鉴权/网络/接口错误显示中文脱敏说明；列表不代表模型能力。
- 切换供应商、修改Key/URL、并发或延迟返回不会串用旧候选，也不会覆盖拉取期间输入。
- 后台请求不阻塞编辑，重复点击不并发重复请求；关闭弹窗/移除备用行时安全处理后台返回。
- 全部配置仍通过既有保存流程；只获取模型不会改变配置或标脏。
- 使用模拟API与Qt离屏测试、截图、全量回归验证；真实供应商由用户验收。

## 风险与回滚

有些中转接口不提供模型列表或列表不完整，始终允许自定义。不保存列表或凭据副本到磁盘。回滚UI与查询方法即可，模型配置仍是原有字符串，无数据库迁移。
