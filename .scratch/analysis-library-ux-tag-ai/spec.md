## Problem Statement

用户在工作台对测试目录（如 9 个视频）点「开始分析」后，进度立刻到满并提示「分析任务已完成」，但状态仍为 pending、几乎无新分析结果。根因是：设定工作范围时视频已入库，而分析逻辑把「已在库」当成「已处理」整批跳过。这导致 **分析 → 打标签 → 模拟/应用重命名** 全流程无法验收。

同时，工作台与素材库日常浏览体验不足：缩略图在未分析时常为空；缺少稳定与当前列表两套序号；卡片视图信息过少且图文不对；删除入口不清晰且语义易与「删文件」混淆；详情区仅有系统播放器级「双击播放」，缺少应用内素材预览（音量/进度/倍速/播放暂停/在文件夹中定位）；列表列与详情字段不能按需显隐，列宽难调且不记忆；底栏占大块空白、详情预览区偏小。

标签体系虽已完成半封闭、归一、待审与冷启动人机流程（`tag-system-depth`），但标签库运营仍偏人工：待审词无 AI 分拣建议、冷启动分簇弱、库内近义重复缺少批量巡检。用户希望标签管理 AI 与主链路同等优先级交付，且所有 AI 建议须人工确认后才写库。

## Solution

1. **分析目标集**：按状态决定是否分析——未分析/失败必跑，已分析默认跳过；提供显式「强制重新分析」（成功后整份覆盖分类/摘要/标签，经标签归一）；禁止「已入库 = 已处理」。
2. **入库即有缩略图**：扫盘入库时轻量抽帧生成缩略图；分析成功可覆盖更优帧。
3. **双编号**：列表序号（当前筛选/排序后 1…n）+ 入库编号（首次入库稳定编号）。
4. **卡片信息固定**：列表序号、入库编号、文件名、分类、状态、标签最多约 2～3（+N）。
5. **删除语义分页**：工作台删除 = 移出工作范围；素材库删除 = 取消入库；默认不删磁盘文件；两页提供显眼删除入口。
6. **素材预览**：详情预览区放大、底栏压成一行状态；内嵌播放（播放/暂停、进度、音量、倍速）+ 在资源管理器中打开所属文件夹并定位文件。
7. **列显示偏好 + 详情字段偏好 + 列宽偏好**：可显隐、可记忆；列可拖宽、双击自适应、可重置；工作台与素材库对齐。
8. **三类标签库 AI**（与主链路同等优先级，均只出建议/草案）：待审词 AI 建议、冷启动 AI 分簇、近义巡检；人工确认后才写入标准词/别名；禁止模糊自动贴词（ADR-0004）。
9. **端到端验收**：在测试工作范围上跑通分析、标准词标签落库、模拟预览与应用重命名。

## User Stories

### 分析主链路

1. As a 剪辑师, I want 工作范围内未分析的视频在点「开始分析」后真正进入分析队列, so that 我不会看到假完成。
2. As a 剪辑师, I want 已分析视频默认被跳过, so that 我不会重复消耗 API 与时间。
3. As a 剪辑师, I want 显式开启「强制重新分析」后对已分析视频再次分析, so that 我能在词表或模型改进后刷新结果。
4. As a 剪辑师, I want 强制重新分析前有确认提示, so that 我不会误覆盖人工改过的内容。
5. As a 剪辑师, I want 强制重新分析成功后分类、摘要、标签（含标签组）被整份覆盖, so that 「强制」语义清晰可预期。
6. As a 剪辑师, I want 分析结果写入前仍经标签归一, so that 半封闭与标准词规则不被绕过。
7. As a 剪辑师, I want 分析失败时条目可标记为失败并可再次进入目标集, so that 我知道哪些没跑通。
8. As a 剪辑师, I want 有勾选时只分析勾选子集（仍在工作范围内）, so that 我可以局部重跑。
9. As a 剪辑师, I want 未勾选时分析工作范围内符合目标集规则的全部条目, so that 不必逐条勾选。
10. As a 剪辑师, I want 分析完成后状态变为已分析且列表/详情可见分类摘要标签, so that 我能继续模拟重命名。
11. As a 剪辑师, I want 对已分析批次做模拟预览与应用重命名, so that 全流程在测试目录可验收。
12. As a 维护者, I want 分析目标集规则可单测, so that UI 改动不会再次把「在库」当成「已分析」。

### 缩略图与编号

13. As a 剪辑师, I want 视频首次入库时就有缩略图, so that 未分析也能辨认画面。
14. As a 剪辑师, I want 分析成功后可用更优帧更新缩略图, so that 预览更代表内容。
15. As a 剪辑师, I want 列表显示当前列表序号, so that 我能说「第 3 个」并快速定位。
16. As a 剪辑师, I want 列表序号随筛选与排序变化, so that 序号始终对应当前可见顺序。
17. As a 剪辑师, I want 每条素材有稳定入库编号, so that 跨会话仍能引用同一条。
18. As a 剪辑师, I want 按入库编号排序, so that 我能按入库先后浏览。
19. As a 剪辑师, I want 列表与卡片同时呈现列表序号与入库编号且文案可区分, so that 我不把两套号搞混。

### 卡片与列表体验

20. As a 剪辑师, I want 卡片正确显示缩略图, so that 网格浏览可用。
21. As a 剪辑师, I want 卡片固定显示列表序号、入库编号、文件名、分类、状态, so that 扫一眼能决策。
22. As a 剪辑师, I want 卡片最多显示约 2～3 个标签其余以 +N 表示, so that 卡片不被标签淹没。
23. As a 剪辑师, I want 工作台与素材库卡片信息一致, so that 两页心智统一。
24. As a 剪辑师, I want 通过列显示偏好隐藏或显示列表列, so that 界面只留我需要的列。
25. As a 剪辑师, I want 通过详情字段偏好隐藏或显示详情字段（如摘要、转录）, so that 详情更干净。
26. As a 剪辑师, I want 隐藏字段不删除已有数据, so that 再显示时数据还在。
27. As a 剪辑师, I want 列宽可拖拽并记住, so that 下次打开仍是我的布局。
28. As a 剪辑师, I want 双击列分隔线按内容自适应列宽, so that 标签列不会长期被挤没。
29. As a 剪辑师, I want 一键重置列宽, so that 调乱后能恢复。
30. As a 剪辑师, I want 工作台与素材库共用同一套列/字段/列宽偏好概念, so that 不必设两遍。
31. As a 剪辑师, I want 详情预览区明显大于底栏空白, so that 预览与播控可读。
32. As a 剪辑师, I want 底部状态栏只占一行摘要（如「素材库共 N 条」）, so that 垂直空间留给列表与预览。

### 删除

33. As a 剪辑师, I want 在工作台用删除把素材移出工作范围, so that 本批不再处理但库记录仍在。
34. As a 剪辑师, I want 移出工作范围后素材库仍能看到该条, so that 总库存不丢。
35. As a 剪辑师, I want 在素材库用删除取消入库, so that 本工具不再管理该条记录。
36. As a 剪辑师, I want 取消入库默认不删除磁盘视频文件, so that 原片安全。
37. As a 剪辑师, I want 取消入库后工作台也不再显示该条, so that 列表与库一致。
38. As a 剪辑师, I want 两页都有显眼的删除按钮（不仅右键）, so that 我找得到入口。
39. As a 剪辑师, I want 删除前有确认且文案区分「移出工作范围」与「取消入库」, so that 我理解后果。

### 素材预览

40. As a 剪辑师, I want 在详情预览区应用内播放当前选中视频, so that 不必跳到外部播放器才能确认内容。
41. As a 剪辑师, I want 播放与暂停, so that 我能控制观看节奏。
42. As a 剪辑师, I want 拖动进度条跳转, so that 我能快速看关键段。
43. As a 剪辑师, I want 调节音量, so that 有声素材也能审听。
44. As a 剪辑师, I want 倍速播放, so that 我能快速扫片。
45. As a 剪辑师, I want 一键在资源管理器打开所属文件夹并定位该文件, so that 我能在外部继续处理文件。
46. As a 剪辑师, I want 工作台与素材库共用同一套素材预览, so that 两页体验一致。
47. As a 剪辑师, I want 素材预览与「模拟预览」文案不混用, so that 我不把播片和重命名预览搞混。

### 标签库 AI

48. As a 剪辑师, I want 对待审词获得 AI 处理建议（批准标准词/挂别名/丢弃及推荐组或目标词）, so that 词表进化更快。
49. As a 剪辑师, I want AI 建议必须我确认后才写入, so that 词表不被模型静默污染。
50. As a 剪辑师, I want 冷启动使用 AI 辅助近义分簇并拟定标准词、别名与分组, so that 草案质量更高。
51. As a 剪辑师, I want 冷启动草案在终审 commit 前可编辑, so that 我能纠正 AI 分簇错误。
52. As a 剪辑师, I want 取消或关闭冷启动不写库, so that 误操作可撤销。
53. As a 剪辑师, I want 对现有标签库做近义巡检得到合并建议清单, so that 我能清理重复标准词。
54. As a 剪辑师, I want 近义巡检的合并须人工确认后执行, so that 不会静默改词表。
55. As a 剪辑师, I want 标签库 AI 不绕过标签归一与硬过滤, so that ADR-0004 仍然成立。
56. As a 维护者, I want 三类标签库 AI 的「建议结构」与「确认后写库边界」可测（可注入假 AI）, so that 不依赖真实大模型做 CI。

### 交叉与文档

57. As a 剪辑师, I want 界面与文档使用 CONTEXT 词汇, so that 概念不混。
58. As a 剪辑师, I want 卡片字段不做逐项显隐, so that 卡片密度保持产品默认。
59. As a 剪辑师, I want 本特性不重新设计侧边栏导航与工作范围模型, so that 与既有 ADR-0001 一致。

## Implementation Decisions

### 架构与 ADR

- 遵循 ADR-0001：工作台 / 素材库 / 工作范围分工；操作默认不超出工作范围。
- 遵循 ADR-0003 / 0004：无独立情绪字段；标签归一硬过滤 + 待审；禁止模糊贴词。
- 产品词一律使用 `CONTEXT.md`。
- 标签库 AI 与分析主链路**同等优先级**交付，但实现可分票；验收上主链路可先在测试目录跑通，标签库 AI 可并行开发。
- 不新增「删磁盘文件」产品能力（本轮 out of scope）。

### 分析目标集（必须可测）

- **输入**：候选路径列表（已由工作范围 + 勾选规则解析）+ 每条当前状态 + 是否强制重新分析。
- **默认纳入**：`pending`、分析失败（或等价失败状态）；可含「从未成功写出分析结果」的条目。
- **默认排除**：`analyzed`（及产品认定的已分析等价状态），除非 `force_reanalyze = true`。
- **禁止**：仅因「路径已在库」而排除。
- **强制重新分析**：UI 显式开关/菜单 + 确认；成功后 **整份覆盖** category、summary、tags、tag_groups；写入前 `apply_tag_normalization`；缩略图可更新。
- **进度与完成文案**：完成数应对「实际尝试分析的条目」诚实；全被跳过时应提示「没有待分析视频」而非伪装 100% 成功分析。
- **与重命名**：模拟/应用重命名继续使用既有整理方案与批次确认；本特性保证分析后字段足够支撑既有重命名变量（标准词 tags 等）。

### 入库编号与列表序号

- **入库编号**：首次成功入库时分配，单调稳定；取消入库后编号不复用给新片的策略由实现选定一种可解释规则（推荐：永不复用全局递增）。
- **列表序号**：纯展示，等于当前代理模型可见行序 1…n；不入库。
- 列表列与卡片均展示二者，表头/标签文案区分「#」与「入库编号」等清晰叫法。

### 缩略图

- 扫盘 `insert_video_if_absent`（或等价入库）路径：异步或同步轻量抽 1 帧写入缩略图路径并关联记录。
- 分析抽帧成功：可覆盖缩略图。
- 列表/卡片/详情均从同一 thumbnail 字段加载；缺失时显示占位，不崩溃。

### 移出工作范围 / 取消入库

- **工作台删除**：从工作范围路径集合移除使该视频不再属于范围（实现可选：移除精确文件路径项，或从文件夹范围中排除单文件——须定义一种可测行为；推荐支持「范围含文件夹时，对该文件记录排除或改为精确路径集合」的简单正确策略，并在 UI 说明）。
- **素材库删除**：删除库记录（及关联缓存/可选缩略图文件清理），**不**删除源视频文件。
- 两页工具栏提供删除按钮；确认对话框文案使用产品词。

### 素材预览

- 位置：详情面板 **详情预览区**（放大）；底栏状态一行。
- 能力：播放/暂停、进度拖动、音量、倍速、打开文件夹并定位文件。
- 与系统默认播放器：可作为补充，不替代应用内控件。
- 切换选中视频时停止或切换当前播放源，避免串音。

### 界面偏好

- 持久化：列显示偏好、详情字段偏好、列宽偏好（工作台与素材库共享同一套键，或分页面键但列概念一致——实现选共享优先）。
- 卡片字段固定，不进显隐开关。
- 列：拖拽改宽、双击分隔线自适应、重置默认。

### 卡片

- 固定信息集见 CONTEXT「卡片信息」；缩略图与列表同源。
- 代理/模型须能提供文件名、分类、状态、标签、双编号与缩略图，而非仅 DisplayRole 文件名。

### 标签库 AI（建议结构，可注入）

**待审词 AI 建议**

- 输入：待审原文、来源组、可选上下文（当前标准词表摘要）。
- 输出建议枚举：`approve_standard`（含推荐 group_id）| `link_alias`（含目标标准词）| `discard`；可附简短理由。
- 确认后调用既有 `resolve_pending_tag` 等价写库路径；未确认不写。

**冷启动 AI 分簇**

- 替换或增强现有 `cluster_fn`：AI 可注入；输出仍为可编辑草案结构。
- commit 边界不变：仅终审写入。

**近义巡检**

- 输入：当前标准词（及可选别名、用量）。
- 输出：合并建议列表（保留词、并入为别名的词、可选组）；批量确认后执行别名挂接/删除冗余标准词（执行规则须不破坏已标注视频——推荐：被合并词作为保留词的别名，并批量把视频上的旧标准词归一到保留词）。
- 禁止静默合并。

### 建议模块边界（无具体文件路径）

- **分析目标集纯函数/服务方法（主接缝之一）**：给定视频记录列表 + force 标志 → 待处理路径列表。
- **入库注册扩展**：分配入库编号、触发轻量缩略图。
- **工作范围变更 API**：移出工作范围。
- **取消入库 API**：删库记录，不删源文件。
- **标签库 AI 门面**：三函数（建议/分簇/巡检），可注入客户端；确认写库走既有标签库 API。
- **UI**：工作台/素材库列表与卡片、详情预览区播放器、偏好显隐与列宽、标签库三入口增强。
- **播放器**：封装为可复用组件挂详情预览区。

### 实现顺序建议（供 to-tickets，非强制）

1. 分析目标集 + 强制重分析覆盖 + 失败可见 + 进度诚实文案。  
2. 入库编号 + 入库轻量缩略图 + 列表/卡片双编号与缩略图修复。  
3. 移出工作范围 / 取消入库按钮与语义。  
4. 列/详情显隐 + 列宽偏好 + 底栏/预览区布局。  
5. 素材预览播控与定位文件。  
6. 待审词 AI 建议、冷启动 AI 分簇、近义巡检。  
7. 测试目录端到端人工验收：分析 → 标签 → 模拟/应用重命名。

## Testing Decisions

### 什么是好测试

- 只断言**外部可观察行为**：目标集包含/排除、覆盖后字段、入库编号稳定性、移出范围后列表成员、取消入库后库中不存在且文件仍在磁盘、AI 建议未确认不写库、确认后写库、列偏好读写结果。
- 不断言 Qt 像素、控件树结构、真实网络模型调用次数。
- 标签库 AI 与分析 AI 一律可注入假实现。

### 测试接缝（Seams）— 请确认

| 优先级 | 接缝 | 锁定什么 |
|--------|------|----------|
| **主接缝 A** | **分析目标集解析** | pending/失败纳入；analyzed 默认排除；force 纳入；禁止「仅因在库而跳过」 |
| **主接缝 B** | **强制重分析写入** | 整份覆盖 category/summary/tags/tag_groups；经归一；非 force 不覆盖已分析 |
| **主接缝 C** | **标签库 AI 边界** | 建议/草案结构；未确认零写库；确认后走 resolve/commit/合并 API；可注入假 AI |
| **次接缝** | **入库编号分配** | 首次入库获得稳定编号；再扫不变更 |
| **次接缝** | **移出工作范围 / 取消入库** | 范围成员变化；库记录有无；源文件仍存在 |
| **次接缝** | **界面偏好读写** | 列显隐、字段显隐、列宽序列化往返 |
| **非自动化默认** | 素材预览播控、卡片绘制、资源管理器定位、真实 API 分析 9 片 | 人工验收清单 |

**刻意不新增**平行业务入口：UI 只调用上述服务/纯逻辑；标签库 AI 不直接改视频标签（巡检合并标准词时通过统一归一/批量替换路径）。

### 将测试的模块行为清单

- 目标集：空列表、全 pending、混合状态、force 开/关、勾选子集。  
- 覆盖：force 后旧标签消失、新标签经别名映射。  
- 入库编号：两次 scan 同一文件编号不变。  
- 删除：工作台移出后素材库仍在；素材库取消后两边皆无；文件仍在。  
- AI：假建议确认/取消；冷启动草案 commit/取消；巡检合并确认后别名表与视频标签一致性。  
- 偏好：设置后读取一致。

### 既有测试 Prior art

- `tests/test_work_scope.py`、`test_ops_filter_scope.py`、`test_tag_normalize.py`、`test_tag_vocab.py` 等服务层/纯函数风格；本特性沿用同一布局与 pytest。

## Out of Scope

- 删除磁盘上的视频文件（含回收站策略）。
- 单片「AI 推荐标签」增强（详情按钮大改；本轮不作为交付必选项）。
- 重新设计整站导航、工作范围模型、标签组无限维度。
- 多语言标签体系、完整配色/图标重构。
- 以真实在线大模型作为 CI 必过条件。
- 新导出格式；重命名产品语义大改（仅保证分析后字段可用）。
- 卡片字段逐项显隐开关。
- 向量相似度自动合并标准词且无人确认。

## Further Notes

- 验收口诀：**真分析**（pending 进队）+ **真图真号**（缩略图/双编号）+ **真预览**（应用内播控）+ **真删除语义**（移出 vs 取消入库）+ **AI 只建议**（确认才写库）+ **全流程**（分析→标签→重命名）。
- 与 `tag-system-depth` 关系：本特性消费其归一/待审/冷启动 commit 边界，不推翻 ADR-0004。
- 与 `workbench-library-split` 关系：不改变工作范围定义；补齐体验与分析队列正确性。
- 范围大：必须分票；建议 frontier 从「分析目标集」开始。
