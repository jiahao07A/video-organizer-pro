## 1. 执行原则

这组 Issue 不按编号顺序逐个实现，而按“安全边界 → 数据基础 → 整理方案 → 历史追溯 → 用户验证”推进。

每个 Issue 在开始编码前必须明确：

- 目标、范围内、范围外和验收标准；
- 对已有 `CONTEXT.md` 和 ADR 的承接关系；
- 是否需要数据库迁移、文件操作、配置迁移或外部服务；
- 失败时保留什么、如何回滚；
- 自动化测试、临时目录测试和 Windows 人工验证方式。

每个实现 Issue 使用独立分支和 PR，不在 `main` 上直接修改。一个 PR 只服务一个 Issue 或一个已经明确批准的任务包。涉及真实视频、真实配置或真实 API 的验证必须使用脱敏小样本，不能把真实素材放入仓库、Issue 或截图。

### G1：确定整理方案和安全语义

**涉及：#17、#19、#16**

必须先书面确认以下三个契约：

#### 操作目标集契约

- 有列表选中时使用列表选中。
- 无列表选中时使用当前可见列表全部。
- 工作台结果必须属于工作范围。
- 当前筛选、排序、选中状态变化后，摘要、确认框和执行结果使用同一批路径快照。
- 分析在操作目标集之上再应用分析目标集规则；不改变 ADR-0005 的跳过、重试和取消语义。

#### 写盘安全契约

为每种动作定义改变对象、预览内容、确认要求、记录内容和恢复边界：

- 分析：数据库写入；是否同步 XMP 由当前配置决定；默认保持自动 XMP 关闭。
- XMP：生成或覆盖侧车文件；不能宣传为原视频完全可恢复。
- 重命名：记录源路径、目标路径、XMP 侧车变化、冲突和外部修改。
- 物理整理：记录源路径、目标路径、目标存在冲突、权限错误和移动结果。
- 导出：记录导出目标、目标集、写出字段数量和失败项；导出不改变原视频。

#### 整理方案与素材批次契约

建议使用不可变的整理方案快照和可追踪的执行记录。至少包含：

- `plan_id`、创建时间、工作范围快照、操作目标集快照、筛选摘要；
- 每个素材的当前状态和目标状态；
- 每项操作的类型、源值、目标值、风险、冲突、是否排除和是否可恢复；
- 用户排除记录、确认时间和配置/词库版本；
- 执行后的成功、失败、跳过、取消、冲突、可恢复和不可恢复结果；
- 外部文件变化检测结果。

需要明确的产品决定：整理方案是否允许在确认后再次编辑、不同操作是否按顺序执行、部分操作失败后是否继续后续操作、重复执行同一方案如何处理、批次记录保存多久以及结果存储在 SQLite 还是独立的管理数据目录中。

**G1 未确认前禁止**：把重命名、移动、XMP 和导出直接拼成一个不可分割的“自动整理”按钮，或新增“全部回滚”承诺。

### G2：确定任务、来源和配置追溯契约

**涉及：#18、#20、#21、#22**

需要统一以下概念：

- **分析任务**：继续只指开始分析/强制重新分析的后台作业。
- **整理方案**：尚未执行的变更计划。
- **素材批次**：一次确认执行所对应的素材集合。
- **任务历史**：分析、整理执行、XMP 和导出等可回看的作业记录。

需要决定任务历史最小字段、状态维度、失败重试入口，以及任务历史与素材批次/整理方案之间的关系。不能用一个笼统的 `status` 同时表示分析完成、人工审核完成和文件整理完成。

AI 来源追溯至少需要：分析时间、模型供应商标识、模型名、Prompt 版本标识、标签库/词表版本标识、标签归一来源、人工修改标识和强制重新分析覆盖差异。不得保存 API Key、完整服务地址或不必要的私人路径。

### 5.2 #19：统一写盘副作用与恢复边界

**当前判断：不能直接实现完整回滚。**

当前代码已经有重命名历史和自动 XMP 开关，但没有统一批次记录。必须先决定：

- XMP 已存在时是覆盖、跳过还是生成冲突；
- 重命名目标存在时如何稳定生成冲突名，不能依赖当前时间造成不可复现结果；
- 物理移动是否允许跨磁盘，失败后是否继续；
- 外部修改源文件、目标文件存在、权限不足时是否跳过并要求人工处理；
- 回滚是否按单项、按操作类型或按整个素材批次；
- 没有原文件快照时哪些内容明确不可恢复。

边界确定后先实现只读预览和冲突检查，再实现执行和恢复。不得先做一个名字叫“全部回滚”的按钮。
