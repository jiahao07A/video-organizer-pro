# Spec: 标签系统深度优化（半封闭 · 精瘦 · 归一）

Status: ready-for-agent  
Created: 2026-07-20  
Feature-slug: `tag-system-depth`  
ADRs: [0002](../../docs/adr/0002-slim-analysis-fields.md)（情绪部分由 0003 取代）, [0003](../../docs/adr/0003-merge-emotion-into-mood-tags.md), [0004](../../docs/adr/0004-tag-normalize-hard-filter-pending.md)  
Glossary: 见根目录 `CONTEXT.md`（标签、标签组、氛围、封闭组、建议组、分析用词表子集、标准词、别名、词表冷启动、标签归一、待审词、分析结果、导出结果、高级筛选）

## Problem Statement

用户依赖标签在**工作台 / 素材库**里找片，并希望同一套词能写进**导出结果**供剪辑软件检索。当前标签体系存在三类痛点：

1. **准确度不稳**：词表近义/重复多（草稿词表与占位「测试\*」并存）；独立「情绪」字段与「氛围」标签组语义重叠，AI 要填两套近义词；模型输出库外词或别名时缺乏统一落库规则。  
2. **容易臃肿**：若把标签库全量塞进分析提示词，或允许开放造词且自动入库，模型选词负担上升，输出更易乱/漏，与「AI 要能正常打标签」冲突。  
3. **冷启动空白**：标签配置里封闭组仍是占位词，草稿词表不能直接当正式库用；用户缺少「整理 → 终审 → 可用」的明确路径。

用户目标明确：**提高打标准确度**，同时**控制复杂度与体量**，避免标签系统本身拖垮 AI 分析。

## Solution

建立以**检索为主、导出为次**的受控标签体系：

1. **半封闭选词**：氛围 / 主体 / 场景 / 动作 为**封闭组**（只从标签库标准词选）；**建议组**可少量自造，仅挂在该视频上，收编入库须人工确认。  
2. **精瘦分析用词表子集**：每次分析只把每封闭组约 15～25、合计约 80～100 的**标准词**送入提示词；库可更大，分析时裁剪；别名不进候选。  
3. **情绪并入氛围**：分析结果取消独立情绪字段；高级筛选取消情绪维；导出/重命名去掉 emotion 变量与 Emotion 列；基调统一由氛围封闭组（单选）表达。  
4. **标准词 + 别名**：落库、筛选主词、导出关键字只用标准词；别名用于归一与筛选扩展命中。  
5. **词表冷启动**：从草稿词表自动去重/近义分簇/归组/裁剪，生成标准词+别名草稿，**人工终审后**写入标签库。  
6. **标签归一 + 待审词**：落库前别名→标准词；封闭组库外词丢弃并记入待审；禁止模糊近邻贴词；待审可批准为标准词、挂别名或丢弃。

## User Stories

1. As a 剪辑师, I want 标签主要用于在工作台和素材库里筛选素材, so that 我能稳定找到可用的片。  
2. As a 剪辑师, I want 同一套标签能写入导出结果供剪辑软件检索, so that 我不必维护两套词表。  
3. As a 剪辑师, I want 当「库内好筛」与「导出好看」冲突时以检索一致性优先, so that 库内筛选结果可预期。  
4. As a 剪辑师, I want AI 在氛围/主体/场景/动作上只从标签库标准词中选择, so that 核心检索维度干净可控。  
5. As a 剪辑师, I want AI 能在建议组补充少量自由细节词, so that 画面特有信息不会因词表不全而完全丢失。  
6. As a 剪辑师, I want 建议组新词默认不自动进入标签库, so that 词表不会被模型随意撑大。  
7. As a 剪辑师, I want 把有用的建议词或待审词人工收编为标准词或别名, so that 词表能随真实素材可控成长。  
8. As a 剪辑师, I want 每次 AI 分析只看到精瘦的分析用词表子集, so that 模型不会因候选过多而打乱或漏标。  
9. As a 剪辑师, I want 分析候选中不出现别名, so that 模型不会在「男/男人/男性」之间摇摆。  
10. As a 剪辑师, I want 标签库可以存比分析子集更多的词, so that 我仍能在界面管理完整词表而不拖垮分析。  
11. As a 剪辑师, I want 分析结果不再包含独立情绪字段, so that AI 不必重复填写情绪与氛围。  
12. As a 剪辑师, I want 情感与视听基调统一落在氛围标签上, so that 筛选入口只有一套。  
13. As a 剪辑师, I want 高级筛选不再提供独立情绪维, so that 不会和氛围/标签筛选打架。  
14. As a 剪辑师, I want 导出与重命名不再使用 emotion 相关变量或 Emotion 列, so that 元数据与产品语义一致。  
15. As a 剪辑师, I want 每个视频在氛围组最多一个标准词, so that 基调检索清晰、不互相矛盾。  
16. As a 剪辑师, I want 主体/场景/动作默认也遵守组内数量上限（默认单选）, so that 每条素材标签总数可控。  
17. As a 剪辑师, I want 建议组有明确数量上限（默认最多 5）, so that 自由词不会淹没标准词。  
18. As a 剪辑师, I want 库内每个含义只有一个标准词, so that 筛选「开心」不会漏掉只标了「快乐」的片（后者应是别名）。  
19. As a 剪辑师, I want 用别名或近义输入时能归一到标准词, so that 人工编辑也不制造脏数据。  
20. As a 剪辑师, I want 用别名做筛选时仍能命中已标标准词的素材, so that 检索更宽松而不污染落库。  
21. As a 剪辑师, I want 导出关键字只写标准词, so that 剪辑软件里的关键字列表干净。  
22. As a 剪辑师, I want 从草稿词表（如行式词表）一键生成冷启动草案, so that 我不必从零想完整词表。  
23. As a 剪辑师, I want 冷启动草案展示标准词、别名与分组建议, so that 我能快速终审。  
24. As a 剪辑师, I want 未经终审的草案不能直接覆盖正式标签库, so that 不会误导入脏词。  
25. As a 剪辑师, I want 终审通过后封闭组达到精瘦可用规模, so that 半封闭分析立刻可跑。  
26. As a 剪辑师, I want 占位测试词（如「测试氛围1」）在冷启动或清理流程中可被替换/清除, so that 正式库不再污染分析。  
27. As a 剪辑师, I want AI 输出别名时自动写成标准词再落库, so that 我不手改也能保持一致。  
28. As a 剪辑师, I want 封闭组库外词被丢弃而不是糊弄贴到「最像」的词, so that 避免错误标签。  
29. As a 剪辑师, I want 被丢弃的封闭组库外词进入待审词队列, so that 我知道模型想表达什么并决定是否扩库。  
30. As a 剪辑师, I want 在标签库相关界面处理待审词（批准标准词 / 挂别名 / 丢弃）, so that 词表进化有固定入口。  
31. As a 剪辑师, I want 待审词与标准词在界面上可区分, so that 我不会把未审词当正式检索词。  
32. As a 剪辑师, I want 建议组库外词可保留在该视频上, so that 细节描述不丢，同时不污染封闭组。  
33. As a 剪辑师, I want 分析提示词明确写出各封闭组「只能从下列标准词选择」及数量上限, so that 模型约束与配置一致。  
34. As a 剪辑师, I want 建议组提示词允许有限扩展并写明上限, so that 自由词可控。  
35. As a 剪辑师, I want 分析 JSON 结构只要求分类、摘要、标签（含标签组）, so that 输出负担保持低。  
36. As a 剪辑师, I want 详情面板不再展示独立情绪, so that 界面与分析结果一致。  
37. As a 剪辑师, I want 旧 emotion 数据被硬删或忽略且无只读入口, so that 不会误以为还能筛情绪字段。  
38. As a 剪辑师, I want 导出扁平关键字来自归一后的标准词（及允许保留的建议组词策略一致）, so that 剪辑软件能搜到。  
39. As a 剪辑师, I want 可选导出「组|标签」层级关键字且仍用标准词, so that 达芬奇等工具能按层级浏览。  
40. As a 剪辑师, I want 标签筛选继续支持任一/全部匹配, so that 检索松紧可调。  
41. As a 剪辑师, I want 按氛围相关标准词筛选素材, so that 能按基调找片（替代原情绪筛）。  
42. As a 维护者, I want 分析用词表子集构建与标签归一是可单测的纯行为, so that 改 UI 不会悄悄破坏半封闭规则。  
43. As a 维护者, I want 禁止模糊近邻贴词有自动化回归, so that 以后没人「优化」回错误贴词。  
44. As a 维护者, I want 冷启动草案结构稳定可测, so that 导入流程可回归。  
45. As a 剪辑师, I want 词表过大时系统自动裁剪进分析子集而不是失败, so that 大库仍能分析。  
46. As a 剪辑师, I want 裁剪策略优先保留高频/启用/组内排序靠前的标准词（实现选定一种可解释规则）, so that 常用词优先进入分析。  
47. As a 剪辑师, I want 在标签库维护标准词、别名、所属标签组, so that 半封闭体系可日常运营。  
48. As a 剪辑师, I want 批量替换标签时结果仍经过标签归一, so that 批量操作也不产生脏标准词。  
49. As a 剪辑师, I want 看到某次分析因硬过滤导致某封闭组为空时仍可接受摘要与建议组, so that 漏标不等于整条分析失败。  
50. As a 剪辑师, I want 产品文档与界面文案使用 CONTEXT 中的词汇（标准词、别名、待审词等）, so that 概念不混。

## Implementation Decisions

### 架构与 ADR

- 遵循 ADR-0003：取消独立情绪；氛围承载基调。  
- 遵循 ADR-0004：标签归一硬过滤 + 待审词；禁止模糊贴词。  
- ADR-0002 中「保留情绪字段」被 0003 部分取代；构图/星级等硬删结论仍有效。  
- 产品词一律使用 `CONTEXT.md`。  
- 与 `workbench-library-split` 的交叉点：高级筛选中的 **emotions 维删除**；若该特性已实现情绪筛，本特性负责拆除并对齐氛围/标签筛选。

### 领域规则（必须可测）

**半封闭**

- 封闭组：`mood`（氛围）、`subject`、`location`、`action` —— 仅标准词；`ai_expandable = false`。  
- 建议组：`custom` —— `ai_expandable = true`；默认 `max_count = 5`。  
- 封闭组默认 `max_count = 1`（与现配置一致，可配置但默认不放大）。

**分析用词表子集**

- 输入：标签库（标准词 + 组 + 可选启用/用量/顺序元数据）。  
- 输出：按组划分的标准词列表；每封闭组目标 15～25；全部候选合计目标 80～100；只含标准词。  
- 超限：按可解释规则裁剪（建议优先级：组内显式顺序 > usage_count > 字典序）；不得把别名或待审词塞进子集。  
- 空组/仅占位：构建结果应可检测，便于 UI 提示「请先冷启动/维护词表」。

**标签归一**

- 输入：原始标签（可按组或扁平）+ 标准词集 + 别名映射 + 组规则。  
- 步骤：去空白 → 别名映射为标准词 → 按组校验成员与 max_count → 封闭组未知词丢弃并产生待审记录 → 建议组未知词可保留（计 max）且不自动入库。  
- 禁止：编辑距离/向量「最近标准词」自动替换。  
- 输出：归一后的 tags / tag_groups；待审词增量列表（含来源视频可选、原文、组、时间）。

**词表冷启动**

- 输入：草稿行列表（如每行一词）+ 当前标签组定义。  
- 处理：去重 → 近义分簇（可用模型或规则，结果必须可被人工改）→ 每簇一个标准词候选 + 别名列表 → 映射到封闭组（无法归入则标「未分组/建议」，不得强行塞封闭组）→ 每组裁到精瘦上限。  
- 输出：草案结构（只读预览）；**commit 动作**才写入标签库与别名表。  
- 默认不自动删除用户已有非占位标准词，除非用户选择「替换/合并」策略（实现须显式确认）。

**分析结果 schema**

- 保留：category、summary、tags / tag_groups。  
- 移除：emotion（及既有 composition、rating、quality_score、is_proxy_needed、tag_weights）。  
- 提示词组装：全局角色头 + 各组 local_prompt + **分析用词表子集** + 半封闭约束 + JSON 结构；不含情绪字段说明。

**高级筛选**

- 删除 emotions / 独立情绪条件。  
- 保留 tags + tag_match_mode；氛围通过标签值筛选即可。  
- 别名扩展命中：筛选输入若为别名，应匹配对应标准词已标注的视频（可在筛选接缝实现）。

**导出 / 重命名**

- 关键字与 `{tags}`：标准词为主；emotion 占位与 ALE Emotion 列移除。  
- 层级导出（若开启）：`组显示名|标准词`；词必须是归一后的标准词。  
- 建议组词是否进入导出：默认进入扁平关键字（利于剪辑检索）；不进入封闭组层级路径以外的「假标准词」晋升。

**待审词**

- 持久化待审队列；状态：pending / approved_as_standard / linked_as_alias / discarded。  
- 批准为标准词时须指定标签组（仅封闭组或明确允许的组）。  
- 挂别名时须指定目标标准词。  
- 待审词永不进入分析用词表子集。

### 建议模块边界（无具体文件路径）

- **标签域纯逻辑（主）**：分析用词表子集构建、标签归一、冷启动草案归约、别名解析。优先纯函数/无 UI 依赖，便于单测。  
- **分析门面**：组装提示词时调用子集构建；解析模型 JSON 后调用归一再写入视频。  
- **标签库 / 配置持久化**：标准词、别名、组规则、待审词、冷启动 commit。  
- **筛选**：去掉情绪维；可选别名扩展匹配。  
- **UI**：标签库（含待审、冷启动终审）、详情（去情绪）、设置提示词预览（反映子集与半封闭）、高级筛选控件。  
- **导出/重命名**：去 emotion；关键字来自标准词。

### 默认配置约定

- 标签组结构保持五组：氛围、主体、场景、动作、建议。  
- 封闭四组 max_count=1；建议组 max_count=5。  
- 精瘦阈值作为默认常量或配置项，允许高级用户改，但产品默认即 B 档。

## Testing Decisions

### 什么是好测试

- 只断言**外部可观察行为**：给定词库/别名/原始 AI 输出/草稿行 → 子集内容、归一结果、待审增量、提示词是否含/不含某约束、筛选是否命中、导出关键字列表。  
- 不断言 Qt 控件树、像素、具体模型 API 调用次数。  
- 不把「调用了真实大模型」作为单元测试必要条件；冷启动近义分簇若依赖模型，应用可注入的假实现锁定归约与 commit 边界。

### 测试接缝（Seams）— 请确认

跨 UI / 配置 / 分析，但自动化应压在**尽量少、尽量高**的接缝：

| 优先级 | 接缝 | 锁定什么 |
|--------|------|----------|
| **主接缝** | **标签域纯逻辑**（子集构建 + 标签归一 + 冷启动草案归约/commit 边界） | 精瘦上限、只含标准词、别名映射、封闭组丢弃+待审、禁止模糊贴词、建议组可保留库外词、草案不经 commit 不入库 |
| **次接缝** | **分析提示词组装**（既有分析门面上的 build prompts） | 无 emotion 字段；含半封闭约束与子集列表；JSON 保留字段集合 |
| **次接缝** | **高级筛选判定** | 无 emotions 参数依赖；标签 any/all；别名扩展命中（若本特性实现） |
| **非自动化默认** | 标签库待审 UI、冷启动终审交互、主题样式 | 人工验收清单 |

**刻意不新增**平行业务入口：UI 与导出只消费归一后的标准词与同一套标签库 API。

> 实现 `/to-tickets` 前请确认：是否同意以上主/次接缝？若希望「提示词组装」也完全并入标签域单一门面，可回复调整。

### 将测试的模块行为清单

- 子集：每组裁剪、合计上限、排除别名、空库/占位可观测。  
- 归一：别名→标准词；封闭组未知→待审且不落库；建议组未知→可落视频；max_count 截断；永不模糊贴词。  
- 冷启动：草案结构；commit 前后库差异；终审拒绝不写库。  
- 提示词：无 emotion；有子集与约束句。  
- 筛选：emotions 相关路径删除或恒忽略；标签匹配回归。  
- 导出/重命名：无 emotion 变量；关键字为标准词。

### 既有测试 Prior art

- 仓库已有筛选、分析结果瘦身、工作范围等相关 pytest 风格测试；本特性应沿用同一测试布局与「服务层/纯函数」偏好。  
- 纠错/拼写（check_spelling）可与别名归一对齐或复用映射表，避免两套近义逻辑；测试应锁「同一别名表」。

## Out of Scope
