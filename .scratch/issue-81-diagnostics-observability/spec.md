# Issue #81：诊断包兼容性与性能观测

GitHub Issue: #81
Branch: fix/81-diagnostics-observability

## 背景和目标

诊断包显示 355 个素材最终成功，但包含远端 502/超时和 `0x8001010e` 原生异常；没有 Windows 10 环境，不能把这些证据外推为已经确定的系统根因。目标是绕开保存诊断包时的原生文件对话框风险，并让后续诊断包包含可比较的阶段耗时和进程资源峰值。

## 范围

范围内：Windows 诊断包保存使用 Qt 非原生对话框；分析任务记录总耗时、抽帧耗时、配置值和低频 CPU/内存/线程/读写峰值；诊断环境白名单包含抽帧相关配置；补充脱敏单元测试。

范围外：不改变并发默认值或 512 上限，不调整解码器、场景检测、API 超时和重试，不宣称已修复 Win10 性能或已消除原生异常，不采集素材与凭据。

## 验收标准

- 保存入口明确设置 `DontUseNativeDialog`，取消不启动后台打包。
- 采样线程在任务结束后停止，采样失败不影响分析。
- 指标 JSON 可序列化，资源峰值单调汇总，路径和配置继续脱敏。
- 既有并发和分析指标测试通过；Win10 原机、真实素材及异常消失情况标记为未验证。

## 风险与验证

本机使用合成样本和 Qt offscreen 测试，不替代 Win10 验收。诊断包历史事实回放单独验证，不写入仓库。若后续包仍有异常，依据新增阶段和资源数据继续拆分问题。
