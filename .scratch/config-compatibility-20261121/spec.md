# 设置中心配置自动升级与兼容适配

## 背景与目标
设置中心已重构，但配置加载仍有字符串版本比较、损坏标签文件回退默认、空路由继承被固定化、扩展字段丢失等风险。统一设置和标签配置的版本检查、兼容补齐、原始备份与原子落盘，让旧配置安全进入新设置中心。

## 范围内
- 为settings/tag_config增加独立配置格式版本；与应用版本、标签业务版本和数据库版本分开。
- 旧配置加载时只做可确定的兼容适配；缺失补默认，支持明确的旧数字/布尔字符串，保留false、0、空列表和继承空值。
- 设置文件旧扁平API→档案/任务路由；已有档案身份、Key、URL、路由显式继承与扩展字段保留。
- 标签旧config列表→tag_groups，保留全局Prompt、组Prompt、导出、分类和扩展字段；语义化比较标签版本，损坏/未来版本不返回默认覆盖。
- 监控路径身份、启用、覆盖和未知字段保留；数据定位记录兼容UTF-8 BOM，不改变搬迁门禁。
- 每个发生变化的既有配置先保存逐字节源备份，再用现有原子JSON写入；升级幂等，备份/写入失败阻止假成功，重试可恢复。
- 加载和保存均拒绝不支持的未来格式，安全错误文案不包含配置值或密钥。

## 范围外
不迁移数据库、不搬迁目录、不导入旧结果或变更业务路由，不改变应用版本，不自动重新打包/替换上一轮已验证安装器，不修改真实用户配置或提交。

## 验收与风险
用合成配置测试旧版、缺字段、BOM、类型适配、未知字段、继承、损坏/未来版本、失败/重试和重复启动；确认原始源快照可还原，正常启动不重复改写。独立文件分别升级，不声称跨文件事务。复用packaging版本比较与storage_backup原子写入，不新增框架。
