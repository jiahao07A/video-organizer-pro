# 工作台跨页门禁修复独立复审 R2

日期：2026-11-14。复审范围：`WorkstationView._has_active_background_task()` 的服务锁及同窗素材库执行角色扩展，以及共享谓词调用路径。仅写本目录独立探针和报告，未修改产品、既有测试、冻结包或真实素材。

## 结论

本轮未发现修复范围内需要再次派发的问题。先前真实复现的 XMP 覆盖缺口在独立期望行为探针中关闭：忙碌时已有侧车保持原字节、不创建工作台 IO 执行线程；释放忙碌后同一真实窗口可以重新确认并真正写入有效 XMP。

## 独立动态验证

新增 `reverse-gate-r2-probe.py`，没有沿用首轮“确认缺口存在”的成功断言。使用真实 `MainWindow`、同窗素材库、真实 QThread、真实临时 SQLite、合成视频与已有 XMP sentinel；服务写盘与 `IoWorker` 均未替换。

- 恢复线程单独、服务分析锁单独、二者同时，各覆盖操作前已忙碌及用户确认期间才启动，共六场景。全部保持 sentinel、不启动 IO；确认前忙碌不弹确认，确认期间启动则由第二次门禁阻止。
- 六场景都在同一窗口正常释放线程/锁，再实际调用 XMP 同步；验证新建真实 IO QThread，实际侧车 XML 可解析，包含合成摘要与标签。
- 工作台/素材库各自的 `_query_worker`、`_detail_worker` 真实活动线程共四场景；这些只读线程保持运行期间实际 XMP 写盘成功，未误挡。
- 六个忙碌场景还验证：后台范围扫描未创建 IO 线程；素材库累加没有改变真实工作范围；工作台恢复中央入口显示“后台任务正在运行”并未创建恢复线程。

独立探针单跑：`10 passed in 12.01s`。

## 共享路径与测试有效性审查

- 范围扫描/浏览/累加保留原有共享谓词，现可观察服务锁及同窗素材库执行线程；没有新增等待或持锁操作，不会引入扫描线程自身持锁后再过门禁的自锁。扫描是在门禁通过后创建线程。
- 素材库 `_reject_workstation_busy()` 可调用工作台谓词，而工作台谓词只直接检查两个 owner 的三个执行角色，不反调素材库 checker，因此没有递归。工作范围冻结、目标快照及确认逻辑未改变。
- 恢复中央入口 `_manual_recovery_busy()` 可调用工作台谓词，谓词不会反向调用中央入口。确认前后检查保留；只读角色继续被排除，已销毁 Qt 包装对象的 RuntimeError 继续忽略。
- 新增 `test_review_workstation_cross_page_gate.py` 的14项使用真实服务、SQLite、同窗页面及实际 XMP。观察 IO 的包装继续调用真实 `run_io_job`，不把替身成功当作实际写盘。另覆盖三个素材库执行角色、确认期间竞态、空闲写盘、只读并行及已销毁包装对象。
- 该14项没有单独覆盖线程与服务锁同时活动、busy释放后的同窗恢复写盘；本次独立探针补充验证这两个组合，没有修改既有测试。
