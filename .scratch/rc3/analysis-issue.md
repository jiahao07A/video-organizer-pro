# [Bug] 单条素材返回 image_url unsafe 时的版本对照与错误处理

背景：用户在 rc2 分析一条测试视频稳定得到 HTTP 400 image_url unsafe，认为 rc1 没有此问题。
目标：用相同输入、配置和依赖比对，明确是否程序回归或服务端对特定内容拒绝，修复证实的问题并给可理解的失败原因。
范围：抽帧、JPEG 编码、请求封装、错误分类及定向测试。范围外：更改/裁剪视频以规避服务端策略、自动换服务商、修改生产库。
初步证据：rc1 与 rc2 的分析核心/网关/路由源码未变化，现有两份抽帧参数和分析路由相同；不能据此排除构建依赖差异或旧缓存影响。
验收：给出同一素材重复请求及正常对照结果、编码有效性与新旧请求差异证据；不可重试拒绝不应进入盲目重试或被误报分析成功。
风险与回滚：测试请求使用已有服务，限制次数，所有凭据本地读取且不输出；只读检查原数据。修复后专项/完整回归和独立子代理评审，批准后提交。
规格：.scratch/rc3/spec.md。
