## 现象

启动应用后，在工作台选中任意视频时，终端反复抛出：

```text
AttributeError: 'AIHandler' object has no attribute 'check_spelling'
```

堆栈：

- `gui.views.workstation.on_selection_changed` → `detail_panel.load_video_data`
- `self.service.ai.check_spelling(tags)` 失败

同次运行还伴随：

1. `QMetaObject::invokeMethod: No such method TagsView::load_data_silent()`（标签库异步刷新）
2. `QFont::setPointSize: Point size <= 0 (-1)`（次要告警，本 issue 不强制处理）

## 验证结果

**已确认（代码 + 运行时 AST/导入检查）。**

- 运行时：`hasattr(AIHandler, "check_spelling") == False`
- AST：`check_spelling` 定义在 **`TagProcessor`**（约 1159 行），不在 `AIHandler`（`AIHandler` 止于 `_simple_fuzzy_match`）
- 详情面板调用的是 `service.ai`（`AIHandler` 实例），属于**错误对象**

## 冗余 / 拒收检查

- 拼写检查逻辑**已实现**在 `TagProcessor.check_spelling`，不是缺失功能，是**调用方挂错类**
- `.out-of-scope/`：无相关记录

## 相关但拆出的问题

- `TagsView.load_data_silent` 未注册为 Qt Slot → 见 issue 02（标签库）
- `setPointSize(-1)` → 可另开，优先级低

## Agent Brief

**Category:** bug  
**Summary:** 详情面板加载视频标签时，向错误的服务对象调用拼写检查，导致选中视频即崩溃。

**Current behavior:**

- 用户在工作台选中一条视频素材时，详情面板尝试对标签做拼写建议。
- 调用路径是 `service.ai.check_spelling(...)`。
- `ai` 是 `AIHandler`，该类没有 `check_spelling`。
- 真正的 `check_spelling` 在 `TagProcessor` 上，运行时抛 `AttributeError`，详情面板加载中断。

**Desired behavior:**

- 选中任意已有分析结果的视频素材时，详情面板正常加载标签、摘要等字段，不再因拼写检查崩溃。
- 若存在拼写建议，仍可通过现有 UI 提示展示；若无建议，静默跳过。
- 拼写检查失败时不得阻断详情面板主流程（防御性：捕获/降级优于整页失败）。

**Key interfaces:**

- `TagProcessor.check_spelling(tags) -> Dict[str, str]` — 权威实现，返回 `{原标签: 建议标签}`
- `AIHandler` — **不应**被误当作拼写检查入口，除非明确做了委托
- 详情面板加载视频数据的路径 — 应通过 service 层可发现的正确协作对象访问拼写检查，而不是硬绑错误类型
- 可选：在 `VideoOrganizerService` 上提供稳定门面（例如委托到 `TagProcessor`），避免 GUI 直接猜模块边界

**Acceptance criteria:**

- [ ] 选中带标签的视频素材时，终端不再出现 `AIHandler` / `check_spelling` 的 `AttributeError`
- [ ] 详情面板完整显示标签与摘要（与崩溃前数据一致）
- [ ] 当 `TagProcessor` 能给出建议时，拼写提示仍可展示；无建议时无异常
- [ ] 拼写检查依赖不可用时，详情仍可加载（降级为空建议）

**Out of scope:**

- 改进纠错算法质量（编辑距离阈值、词典来源）
- 修复 `load_data_silent` Qt Slot（issue 02）
- 修复 `QFont::setPointSize(-1)` 告警
- 统一批次预览/回滚产品流程
