# 04 - 暗/亮主题显示体系不完整（筛选全黑 + 标签库不随主题切换）

Status: resolved

Resolved: 2026-07-20（实现完成，待用户 GUI 验收）

## 现象（用户报告）

1. **工作台 → 高级筛选**：出现与旧版标签库类似的「全黑/难辨认」。
2. **切换暗色主题后**：标签管理界面**仍保持浅色（白）**，不跟随主窗口主题。

用户判断（正确）：与此前标签库 bug **同一类**——暗/亮主题显示体系问题，而不是两个无关 UI 缺陷。

## 验证结果

**已用代码确认（强证据）。**

### 根因模型（统一）

| 症状 | 机制 |
| --- | --- |
| 局部面板在 light 下「全黑」 | 组件硬编码深色底（如 `#252526`），与全局 light 文字/控件对比或混用失败 |
| 切换主题后标签库仍白 | 标签库在构造时读一次 `ui_preferences.theme` 并写死到各控件 QSS/palette；`toggle_theme` 只刷新主窗口 `get_main_style`，**不通知** `TagsView` 重算色板 |
| 02 修复不完整 | 02 引入 `tags_library_palette` 解决了「启动时 light 下可读」，但未做 **主题变更订阅/重绘**，也未扫其它硬编码面板 |

### 证据 1：高级筛选硬编码深色底

`FilterPanel.setup_ui`：

- `self.setStyleSheet("background-color: #252526; border-radius: 8px;")`
- 无主题参数、无 `apply_theme`、不监听全局主题变更

在 light 主题下：面板强制深色底；子控件若走全局 light palette/QSS，易出现「黑底 + 深色字」或「整块黑条」类可读性故障。

### 证据 2：主题切换只刷主窗 QSS

`MainWindow.toggle_theme`：

1. 写 `ui_preferences.theme` light↔dark  
2. `save_settings`  
3. `refresh_style()` → **仅** `self.setStyleSheet(get_main_style(...))`

不调用标签库 / 筛选面板 / 详情面板的局部样式刷新。

### 证据 3：标签库色板只在 `__init__` 解析一次

`TagsView`：

- `_resolve_colors()` 在初始化时调用  
- `create_column` / 热力图使用 `self.ui_colors`  
- **无** `apply_theme` / `on_theme_changed` / 在 `showEvent` 中重读 settings  

因此：用户先以 light 打开（或默认 light）→ 标签库铺白；再切 dark → 主窗变暗、标签库仍白。与报告一致。

### 证据 4：同类硬编码仍散落

至少还有（本 issue 建议一并收敛或列入 out-of-scope 清单）：

- `detail_panel`：`#1a1a1a` 缩略图区等  
- `rename_dialog`：`#262626`  
- 工作台按钮：`#3d5afe` 等强调色（可保留，但应与主题语义一致）

## 冗余 / 拒收检查

- **不是** 02 的重复开新需求：02 只修了启动时标签库 + Slot；本 issue 是 **主题体系补完**  
- `.out-of-scope/`：无

  1. 单一主题色板源（可扩展现有 `get_main_style` 或共享 palette dict）  
  2. 主窗 `refresh_style` / `toggle_theme` 后 **广播** 主题变更，或显式调用各子页 `apply_theme(theme)`  
  3. `FilterPanel`、`TagsView`（及已知硬编码面板）去掉写死 hex，改为跟随当前主题

## Agent Brief

**Category:** bug  
**Summary:** 统一修复 GUI 暗/亮主题：高级筛选与标签库等局部面板必须跟随全局主题，且切换主题后立即重绘，而不是只在首次构造时读一次主题。

**Current behavior:**

1. 高级筛选面板背景硬编码为深色（约 `#252526`）。在浅色主题下表现为整块发黑或文字难辨，与旧标签库问题同类。
2. 标签库在构造时根据当时的 `ui_preferences.theme` 生成色板并写到分栏/列表/热力图；之后用户切换主题时，主窗口 QSS 更新，标签库局部样式不更新（例如切到暗色后标签库仍白）。
3. 主题切换入口只更新主窗口 stylesheet 并保存设置，没有驱动已创建子视图刷新。

**Desired behavior:**

1. 任意时刻，全局主题为 `light` 或 `dark` 时：
   - 工作台「高级筛选」展开后，面板背景、标签文字、下拉与日期控件在**该主题下清晰可读**。
   - 标签库管理页分栏、列表芯片、热力图、搜索框在**该主题下清晰可读**。
2. 在应用已打开时点击「切换主题」：
   - 主窗口与上述局部面板在**无需重启、无需离开再进入页面**的情况下同步切换（若实现选择「再次进入页面才刷新」，必须在 brief 外单独说明并获维护者同意；默认要求即时同步）。
3. 不引入第二套互不通信的主题系统；局部色板与 `get_main_style` 使用的 light/dark 语义一致。

**Key interfaces:**

- `ui_preferences.theme` — 唯一权威主题键（`light` | `dark`；历史其它值需有明确映射）
- 主窗口主题刷新路径（当前为 `refresh_style` / `toggle_theme`）— 必须成为「全局主题已变更」的汇合点，能触达已创建的子视图
- `TagsView`（或等价标签库视图）— 需能根据当前主题重算并重涂色板（含列表 palette / 分栏 QSS / 热力图）
- `FilterPanel`（或等价高级筛选面板）— 禁止仅硬编码单一深色背景；需跟随当前主题
- 可选：共享 palette 字典或主题 token，供多控件复用，避免再复制 hex

**Acceptance criteria:**

- [ ] 全局 theme=`light`：打开高级筛选，面板与控件可读，无「整片黑块」
- [ ] 全局 theme=`dark`：打开高级筛选，面板与控件可读
- [ ] 全局 theme=`light`：标签库可读
- [ ] 全局 theme=`dark`：标签库可读
- [ ] 从 light 一切换到 dark：主窗与标签库、高级筛选均变为暗色风格（无需重启）
- [ ] 从 dark 一切换到 light：主窗与标签库、高级筛选均变为浅色风格（无需重启）
- [ ] 不回归：标签库 `load_data_silent` Slot 仍可用；选中视频详情不因主题刷新崩溃

**Out of scope:**

- 全新第三主题（如 high-contrast）产品设计  
- 重做整站视觉品牌（只修主题一致性与可读性）  
- 修复 `check_spelling`、Prompt 配置（已另 issue）  
- 必须重写所有历史按钮强调色（可在本 issue 内顺手改明显冲突项，但不是验收门槛）
