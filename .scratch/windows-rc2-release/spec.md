## 依赖、风险与回滚

- 发布依赖计划纳入的 PR 通过审阅和验收。PR #32 当前未获非作者批准，且可见 Windows GUI 走查和脱敏视觉证据缺失；这是当前阻塞项。PR #33 当前仍为 Draft，不自动纳入 RC2；如将来决定纳入，须先转为可审阅 PR 并完成其审阅及验收。
- 根工作区现有 `build/` 和 `dist/` 包含运行时配置与数据库；`build.py` 会在当前工作目录下无条件尝试删除这两个目录，再调用 PyInstaller。构建只允许在发布工作树中直接调用 PyInstaller，并为 `--workpath`、`--distpath` 指定全新隔离路径；不得调用会清理默认目录的 `build.py`。压缩前仍须审计全部包内文件，不能只依赖 `build_app.spec` 的声明。
- 若构建或冒烟测试失败，停止发布，不清理或覆盖旧产物；修复后重新构建到全新隔离目录。发布后发现缺陷时不移动或复用 RC 标签，以新提交发布后续候选版本。

## 验证计划

1. 发布前重新获取并核实 PR 审阅、CI、人工验收及 `origin/main` 提交。

5. 计算并记录 SHA-256；经发布授权后创建标签和 Release，发布后再次核对标签 commit、资产与校验值。
