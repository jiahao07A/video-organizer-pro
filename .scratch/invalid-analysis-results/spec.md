# 阻止无效分析结果污染素材与文件名

Status: resolved
GitHub Issue: #73 — https://github.com/jiahao07A/video-organizer-pro/issues/73
Branch: fix/73-invalid-analysis-results
PR: https://github.com/jiahao07A/video-organizer-pro/pull/76

## 背景与目标

RC7 与 RC8 存在同一缺陷：合法 JSON 中的失败性摘要被当作分析成功，进入缓存、数据库及文件名。现场诊断记录显示 175 个视频各抽取 8 帧，不支持“本地抽帧失败”的解释。本次修复应用端的结果可信边界，不推断供应商后端实现。

## 范围

- 在视频分析业务边界统一校验新响应、持久缓存和恢复上下文缓存。
- 无效结果不得写缓存、标为成功、写入标签副作用或触发音频/文件写入。
- 接入现有有界单条重试和批次补跑、失败分类与手动恢复，保留旧有效成果。
- 重命名前识别明确污染的旧摘要，并按条报告，不让一个失败项中断整批。
- 覆盖预览界面与自动监控重命名入口，避免异常冒泡或虚报成功。
- 复用现有成熟的结构校验依赖，避免自建通用校验框架。

范围外：更换用户模型、修改凭据、自动重命名或删除真实素材、静默批量修订旧数据库。用户于 2026-11-14 明确追加提交、合并与发布授权；本轮加入下一未占用候选版本 `0.0.1-rc9`，仅在 PR 获批合并后从 `main` 构建并发布。

## 验收与防御测试

1. 失败性摘要、显式错误状态、缺字段、错误字段类型均不能成为成功分析结果。
2. 正常中英文摘要、描述屏幕错误提示的画面、单选字符串与多选标签、空标签组均可正常分析。
3. 无效缓存被忽略并重新请求；重试不复用无效上下文；有效缓存仍可命中。
4. 重试数量受现有配置和恢复预算限制，取消后不再提交新请求。
5. 分析失败可在失败中心查询，归为响应问题而非本地解码；错误文本不包含原始响应、密钥或图片。
6. 强制重新分析失败保留旧有效成果；新失败不会写待审标签、使用计数、XMP 或媒体元数据。
7. 明确错误摘要不能经预览、批量执行或监控自动流程进入文件名；正常项继续执行，失败项正确计数。
8. 旧素材无摘要时仍可使用只含原名/日期的自定义重命名；不以泛化关键词“失败”误杀真实画面描述。
9. 增补真实抽帧到实际临时重命名的回归，以及多素材并发隔离验证。

## 约束、风险与回滚

- 不改数据库版本，不对旧素材执行启动时自动清理或自动发起收费请求。
- 语义识别仅拦截明确的模型自述失败和错误标志，不承诺识别所有幻觉；主要误判风险由反例测试控制。
- 修复和测试均在独立分支；既有其他任务的未跟踪文件保持原状。
- 用户验收并批准后才 commit，后续通过 PR 集成。回滚通过还原本次代码提交，不涉及数据结构回滚。
