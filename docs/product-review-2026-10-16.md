# 视频素材整理工具产品与交互评审报告

- **评审日期**：2026-10-16
- **评审对象**：本地 Windows 视频素材整理工具
- **主要读者**：产品经理、设计师、项目负责人
- **评审范围**：产品主流程、信息架构、批量操作语义、AI 结果审阅、安全感、异常恢复和长期使用效率
- **本轮不评审**：代码回归、自动化测试覆盖率、具体线程或数据库实现、最终性能基准

## 1. 结论先行：产品已过原型期，下一步应收束主流程

项目已经具备继续产品化所需的能力基础：工作台、素材库、标签库和系统设置已经形成主要界面分工；项目材料还确认了工作范围、操作目标集、分析目标集、分析重试与双进度、标签归一、待审词审核、重命名模拟预览、导出和部分回滚等能力或产品决策。

当前所处阶段不是“继续堆功能”，而是从**功能集合**过渡到**可信的批量整理流程**。用户应能沿着一条连续路径完成：

> 设定工作范围 → 生成分析结果 → 形成整理方案 → 审核并排除变更 → 批次确认 → 执行 → 查看结果与恢复边界

目前材料显示，分析、重命名、物理整理、XMP 和导出仍主要以多个入口存在，尚未统一为一个可审阅、可确认、可追踪的整理批次。最高优先级应是建立**整理方案与批次中心**，而不是新增更多零散入口。

### 当前最关键的五个问题

1. **没有统一的整理方案和批次中心**：用户需要自行拼接分析、审核、重命名、移动、XMP 和导出，执行结果也缺少统一记录。
2. **操作目标集没有持续显式呈现**：用户难以确认当前动作到底作用于列表选中，还是筛选后的可见列表。
3. **XMP、物理移动、重命名和回滚的安全语义不统一**：只读分析与写盘副作用之间的边界还不够清楚，恢复能力也容易被过度理解。
4. **AI 结果缺少完整审阅依据**：用户看得到结果字段，却不一定看得到来源、归一过程、版本信息和人工修改痕迹。
5. **已有分析进度和重试基础没有进入任务中心**：双进度、重试和补跑是已有基础能力，应被纳入统一任务历史，而不是再规划成另一套分析功能。

### 建议的下一阶段目标

用一个可追踪的整理批次承载从分析到执行的完整过程，并以四个结果作为阶段验收标准：

- 用户在每个批量动作前都能确认**操作目标集**和处理条数。
- 用户在执行前能逐项审核**整理方案**，排除文件或某类操作。
- 用户能明确区分分析完成、人工审核完成、文件操作完成和导出完成。
- 用户能在批次结束后查看成功、失败、跳过、冲突及可恢复范围。

## 2. 证据边界与阅读方式

本报告依据以下项目材料形成：

- 根目录 `README.md` 的产品定位、功能地图、目标工作流和当前代码状态说明。
- 根目录 `CONTEXT.md` 的领域术语和操作边界。
- `docs/adr/` 中关于工作台/素材库分工、标签归一硬过滤与待审词、分析重试与双进度、任务模型路由等已接受决策。
- 项目中的规划材料、规格记录、当前界面入口和设置相关材料。

报告使用三种证据标签，避免把计划或推断写成已验证事实：

- **已从项目材料确认**：可从 README、CONTEXT、ADR、规划或当前入口中直接确认，表示“有入口”或“已有决策”，不等于完成了端到端验收。
- **合理推断**：根据现有入口、规则和典型使用路径推断出的体验风险，仍需要用户走查或桌面端验证。
- **需要真实用户或桌面端到端验证**：不能仅凭静态材料判断，需通过真实用户、真实素材或桌面端操作确认。

本报告不复述任何 API Key、服务地址、私人路径或真实素材信息。除非特别说明，文中的“当前已有”均不代表已经完成正式可用性测试。

## 3. 当前产品状态

### 3.1 已形成的产品基础

以下能力或方向可以从项目材料确认：

- **工作台**处理当前工作范围，**素材库**浏览全部已入库视频素材；两者均有高级筛选方向。
- 工作范围支持路径替换和累加；素材库可将操作目标集中的视频路径累加到工作范围。
- 批量操作遵循操作目标集规则：有列表选中时处理选中集合；无列表选中时处理当前可见列表全部。工作台操作不得超出工作范围。
- 列表/卡片视图、缩略图、列表序号、入库编号和素材预览已构成素材辨认基础。
- 分析目标集会在操作目标集基础上跳过已分析条目；未分析或失败条目进入分析，强制重新分析需要用户显式选择。
- 分析任务已有调用层重试、单条层重试、批次补跑、总进度、子进度和分析行临时态等决策。
- 标签归一采用标准词、别名、封闭组硬过滤和待审词；待审词处理需要人工确认，不能静默写入标签库。
- 标签库包含待审词审核、标准词维护、标签组、别名、标签移动、导入和近义巡检等方向；近义巡检是次要运营入口。
- 重命名模拟预览、应用重命名、物理整理、XMP 同步和 FCPX/ALE 等导出入口已有产品基础或规划基础，但是否完整贯通本轮仍待验证。
- 模型供应商与任务模型路由已有明确分工；冷启动 AI 分簇当前停用，不应列为下一阶段主线。

### 3.2 当前体验的核心断点

这些能力尚未自然汇聚成用户可理解的状态链：

- 用户看到的是多个功能入口，未必知道“现在处于分析、审核、整理还是输出阶段”。
- 系统内部可以区分分析状态、人工编辑和文件操作，但用户看到的状态不一定能回答“下一步该做什么”。
- 操作目标集规则已明确，但界面若不持续展示，用户仍需依赖记忆确认批量范围。
- README 和领域规则已经说明副作用与回滚边界，但点击具体动作时未必能看到同等明确的风险提示。

因此，下一轮应优先补足流程、目标和结果的可见性，再扩展低频能力。

## 4. 优先级框架

- **P0**：影响核心任务完成、素材安全感或结果可信度；下一阶段必须处理。
- **P1**：明显增加理解成本、重复操作或长期维护成本；核心批次流程稳定后处理。
- **P2**：提升专业度、舒适度或规模适应性；不应抢占 P0/P1 资源。

## 5. P0 问题：先建立可信的批量整理主线

### P0-1：缺少统一的整理方案、批次确认和结果追踪

**现状**

项目材料确认分析、模拟整理、重命名、物理整理、XMP 和导出分别存在入口或产品方向，但它们尚未被统一为一份整理方案和一个批次。分析结果、目标文件名、目标目录、元数据变更和导出动作之间缺少共同的用户可见身份。

**用户影响**

- 用户要在多个入口之间自行判断哪些文件属于同一轮处理。
- 用户不能在一个地方排除某个文件或排除某类操作。
- 执行后难以一次看到成功、失败、跳过、冲突和后续可恢复动作。
- “分析完成”容易被误解为“文件已经整理完成”。
- 发生问题时，只有部分重命名恢复能力不能满足用户对整批恢复的预期。

**产品建议**

建立以“整理方案”为核心的四阶段流程：

1. **建立工作范围**：显示路径项、范围内素材数、未分析数和失败数。
2. **生成整理方案**：分析只生成分析结果和建议；方案集中展示分类、标签、摘要、目标文件名、目标目录、XMP 和导出动作。
3. **方案审核**：按文件和按操作类型查看差异；支持排除单个文件、排除重命名或移动、只保留标签变更等明确操作。
4. **批次确认与执行**：用户一次确认后生成批次记录；执行中和执行后显示结果，完成后进入任务中心或批次历史。

整理方案必须明确区分“尚未执行的计划”和“已经执行的结果”；模拟预览是前者，批次回滚是后者。

**验收信号**

- 用户可以从一个入口查看本批次的文件范围、分析结果和待执行变更。
- 用户可以排除一条素材或一类变更，并在确认摘要中看到处理条数变化。
- 执行完成后能查看成功、失败、跳过、冲突和可恢复范围。
- 用户走查时能准确说出“分析完成”和“整理完成”的差别。

### P0-2：操作目标集没有在批量操作界面中显式呈现

**现状**

操作目标集规则已经确定：列表选中优先，无选中则当前可见列表全部；工作台仍受工作范围边界约束。当前风险在于，规则如果只存在于说明或实现中，工具栏、确认框和结果页就无法持续提醒用户本次处理对象。

**用户影响**

- 用户容易忘记当前是否有列表选中。
- “当前可见列表全部”可能被误解成工作范围内全部或素材库全库。
- 分析、导出、物理整理、移出工作范围和取消入库都使用同一目标集规则，但危险程度不同，用户需要重复猜测。
- 筛选条件变化后，用户不易发现目标数量已经变化。

**产品建议**

在工作台和素材库的批量操作区固定显示“操作目标集摘要”，至少包括：

- 当前工作范围：路径项数量和素材数量；素材库可显示“全库浏览”。
- 当前筛选：主要条件摘要。
- 当前列表选中：选中数量；无选中时明确写“当前可见列表全部”。
- 当前动作将处理的确切数量。
- 对移出工作范围、取消入库、物理整理、重命名和 XMP 等动作，明确写出是否会改变磁盘文件、是否生成侧车、是否越过工作范围。

所有确认框沿用同一摘要结构，确认文案写清产品语义，例如“移出工作范围”或“取消入库”，不使用含义宽泛的“删除”。

**验收信号**

- 任一批量动作执行前，用户无需操作试错即可回答“这次会处理哪些素材”。
- 无列表选中时，界面明确显示当前可见列表条数，且不把被筛选隐藏的条目计入目标集。
- 工作台操作不会把工作范围外素材带入目标集。
- 目标集条数在筛选、选中和取消选中后即时更新，并与确认框一致。

### P0-3：XMP、物理移动、重命名和回滚缺少统一且准确的安全语义

**现状**

项目材料已经把分析与文件变更区分开，也确认 XMP 具有写盘副作用；同时，物理整理、重命名和回滚的覆盖范围并不相同。当前本机设置中存在“自动 XMP 状态”需要确认的配置风险，列宽设置还存在旧列索引和文件名列宽异常的提醒。静态材料不能证明所有写盘和恢复路径都已完成端到端验证。

**用户影响**

- 用户可能把“开始分析”理解为只读操作，却在分析后发现生成或覆盖了 XMP 侧车。
- 用户无法快速查看大量文件的完整源路径到目标路径差异。
- 用户可能把“回滚”理解为整批完全恢复，而实际只覆盖部分重命名或记录条件。
- 设置、文档和本机状态不一致会削弱用户对安全模式的信任。

**产品建议**

- 提供明确的素材安全模式；默认把分析与写盘动作分开，分析是否自动同步 XMP 必须在操作附近可见。
- 开启自动 XMP 前说明作用时机、影响条数及“生成或覆盖 XMP 侧车”的含义。
- 物理整理和重命名的模拟预览提供可搜索、可排序、可排除的完整源路径→目标路径列表，并显示冲突。
- 对每种恢复能力使用准确名称，分别说明重命名恢复、移动恢复、XMP 恢复或不可恢复范围；不使用超出实际覆盖范围的“全部回滚”表述。
- 每个批次结束时显示已恢复、可恢复、不可恢复和因外部文件变化而需要人工处理的范围。
- 对设置风险提供“恢复默认布局”入口，修复旧列宽索引或文件名列宽异常时不要求用户自行编辑配置。

**验收信号**

- 默认分析模式下，用户能在开始前看到是否写入视频或 XMP；若开启自动 XMP，确认框显示明确副作用。
- 移动和重命名执行前，用户能检索并审阅完整的源路径→目标路径方案。
- 回滚入口会说明实际覆盖范围和前置条件；恢复失败或文件已被外部修改时会单独列出。
- 本机设置中的自动 XMP 状态和列宽异常可以通过用户可见设置处理，而不暴露敏感配置内容。

### P0-4：AI 结果可见字段多，但审阅依据不足

**现状**

分析结果以分类、摘要和标签等结果字段呈现；标签归一、标准词、别名、封闭组、建议组和待审词已有明确规则。但从用户视角，尚不一定能看出一个标签是标准词命中、别名归一、建议组新词、人工修改，还是因硬过滤进入待审词。模型、Prompt、标签库版本和分析时间也应成为可追溯信息，而不是只留在后台材料中。

**用户影响**

- 用户难以判断哪些结果可以直接接受，哪些需要复核。
- 出错时难以区分模型判断问题、标签库覆盖不足和标签归一丢弃。
- 强制重新分析会整份覆盖分类、摘要和标签，人工修改可能被覆盖；如果没有差异提示，用户容易误操作。
- AI 输出越多，用户越容易把建议误认为事实或已确认的标准词。

**产品建议**

在素材详情和整理方案中增加结果来源与审阅信息：

- 分析时间、模型供应商、模型名、Prompt 版本和标签库版本。
- 每个标签的来源：标准词命中、别名归一、建议组新词或人工添加。
- 封闭组被硬过滤、进入待审词或建议组保留时，显示简短原因。
- 对分类、摘要和标签提供“接受 AI 结果”“编辑”“恢复 AI 结果”等明确动作，并保留人工修改痕迹。
- 强制重新分析前展示将被覆盖的人工字段和差异，要求用户显式确认。
- 增加“需要复核”筛选，不能只依赖未分析、已分析和失败等状态。

标签库 AI（待审词 AI 建议、批量待审 AI 分拣、近义巡检和标准词 AI 助手）继续只产出建议；写入标准词、别名或改组仍须人工确认。

**验收信号**

- 用户能从详情或方案中回答某个标签的来源和当前是否已人工确认。
- 强制重新分析前，用户能看到会覆盖哪些人工修改，并可以取消操作。
- 封闭组库外词不会被静默贴到最近标准词；待审词的后续处理可被用户找到。
- AI 结果中的模型、Prompt 和标签库版本可以在批次记录中追溯。

## 6. P1 问题：在主流程基础上降低长期认知负担

### P1-1：分析已有双进度和重试基础，但缺少统一任务中心

**现状**

分析任务的总进度、子进度、调用层重试、单条层重试、批次补跑和取消边界已经在 ADR 中明确，是当前较成熟的基础能力。问题是这些反馈主要停留在分析过程；任务结束后，分析、导出、XMP 和物理整理的历史、失败项和恢复范围缺少统一的用户入口。

**用户影响**

- 任务结束后用户难以回看某条素材为何失败。
- 失败项需要重新寻找入口，可能被迫重跑整个目标集。
- 双进度和批次补跑的含义不能沉淀为可追踪历史。
- 用户无法判断任务是否还存在可恢复动作。

**产品建议**

建立任务中心或批次历史，将已有分析双进度纳入其中，而不是重新设计一套重试规则。每条记录至少显示任务类型、开始/结束时间、目标数量、成功/失败/跳过/取消/冲突数量、失败原因、逐项重试入口、实际使用的模型配置和可恢复范围。

**验收信号**

- 分析任务完成后仍可查看总进度、补跑段和最终结果，不需要依赖临时弹窗。
- 用户可以仅重试失败项，不必默认重跑整批。
- 任务历史清楚区分分析任务、整理执行和导出任务；不把重命名等长任务套用分析重试语义。

### P1-2：状态应服务用户决策，而不只是反映实现过程

**现状**

材料中同时存在分析状态、分析行临时态、人工编辑、重命名、XMP 和导出等状态来源。分析行临时态按决策不写入素材库持久 `status`，但用户仍需要一个能回答“下一步该做什么”的可见状态组合。

**用户影响**

- “已完成”可能同时指分析完成、人工审核完成或文件整理完成。
- 用户难以筛选“待我审核”“需要重审”“存在文件冲突”等行动对象。
- 临时态、持久状态和文件副作用混在一起时，容易产生错误预期。

**产品建议**

在界面上按用户任务拆分状态维度：

- **分析状态**：未分析、分析中、待复核、已分析、失败、已取消。
- **人工状态**：未审核、已审核、人工修改、需要重审。
- **文件操作状态**：未整理、已重命名、已移动、存在冲突、可恢复、恢复部分失败。
- **导出状态**：未导出、已导出、导出失败、XMP 已同步。

列表只展示最重要的一到两个状态，其余放入详情和筛选；分析中的临时态继续只用于任务期间的显示。

**验收信号**

- 用户能按行动目标筛选待复核、失败、冲突和可恢复素材。
- 分析成功不会自动显示为“已整理”；文件操作完成也不会掩盖分析失败。
- 任务结束或应用重启后，分析行临时态不会被误当成持久状态。

### P1-3：工作台与素材库之间缺少连续的跨页心智

**现状**

工作台负责工作范围内的处理，素材库负责全库存浏览；素材库可以将操作目标集中的路径累加到工作范围。这套职责分工是正确的，但从当前流程看，用户仍需手动完成筛选、累加和切换，缺少明确的“带着当前目标进入下一步”动作。

**用户影响**

- 用户需要记忆入库记录、工作范围、列表选中和素材批次的区别。
- 从素材库筛选出一组素材后，切换到工作台的连续性不足。
- 用户不容易知道某条素材是否已在当前工作范围。

**产品建议**

- 提供“将当前结果作为工作范围”和“追加到当前工作范围并开始分析”等明确动作。
- 显示最近工作范围或可命名工作集；不要把工作集与素材批次混为同一概念。
- 在素材库标记已在当前工作范围的条目，在工作台显示工作范围来源。
- 从素材库详情跳转到工作台时保留列表选中和操作目标集语义。

**验收信号**

- 用户能从素材库筛选结果直接创建或追加工作范围，并看到追加条数。
- 跨页后仍能解释哪些是工作范围、哪些是本次操作目标集、哪些是素材批次。
- 工作范围的路径边界没有因跨页操作被静默扩大。

### P1-4：待审词审核和标准词维护仍有认知负担

**现状**

待审词是标签归一后的主审路径，标准词必须属于标签组；近义巡检是次要入口。当前涉及批准到组、挂别名、丢弃、单条 AI 建议、批量待审 AI 分拣和标准词移动等动作，若依赖多个弹窗、自由文本和隐性拖拽，用户需要在操作时记忆较多规则。

**用户影响**

- 用户看不到待审词的来源、出现次数、相关素材和建议目标。
- “挂别名”使用自由文本时，容易拼错或误指向标准词。
- 批量 AI 建议若不能明确“应用选中”，用户可能误以为整批都会写入标签库。
- 标准词移动依赖拖拽或右键时，入口可发现性和影响范围不够清楚。

**产品建议**

- 将待审词设计为可搜索、筛选、排序的审阅队列；行内展示原词、来源组、出现次数、相关视频数、推荐动作、推荐目标和处理状态。
- 挂别名使用可搜索的标准词选择器；批准新标准词必须明确选择目标标签组。
- 批量待审 AI 分拣仅在用户多选并点击“应用选中”后写库，未选中的建议不生效。
- 标准词管理优先提供搜索、按组筛选、批量移动和变更确认；拖拽保留为快捷方式而非唯一主路径。
- 近义巡检与标签使用统计保持次要入口，不抢占待审审核的日常主层级。

**验收信号**

- 用户可以连续处理待审词，不必为每条词打开难以回看的自由文本弹窗。
- 批量操作前后都能看到选中条数、目标组和实际写入条数。
- 待审词、标准词、别名和素材上的历史原文在界面层级上可区分。
- 任何 AI 建议都不会绕过人工确认、标签归一或封闭组硬过滤。

### P1-5：设置中心需要突出“当前生效配置”和副作用

**现状**

设置已经覆盖模型供应商、任务模型路由、Prompt、界面偏好、分析重试和导出等内容；任务模型路由也已确定六个固定 AI 功能槽位。设置功能较完整，但日常偏好、高级配置、费用影响和文件副作用之间的层级仍需要更清晰。

**用户影响**

- 用户不容易知道某个 AI 功能实际使用哪个模型供应商和模型名。
- 自动 XMP、音频转录、批次补跑和导出配置的影响不集中显示。
- 普通界面偏好和敏感连接配置的保存语义可能被混淆。
- 配置不一致或迁移异常时，用户只能从异常界面反推原因。

**产品建议**

在设置顶部增加“当前生效配置”摘要，显示：当前供应商及各任务模型路由、分析是否会写 XMP、是否启用自动批次补跑、Prompt 与标签库版本、最近连接测试结果和配置下一次生效时间。将安全与副作用作为高优先级分组；连接测试、恢复默认布局和配置版本回看应比低频导出字段设置更容易找到。

**验收信号**

- 用户可以不打开多个设置页就知道当前任务使用的供应商和模型。
- 用户能在开始分析前确认 XMP、补跑和其他副作用状态。
- 自动保存和手动保存的设置类型有明确提示；保存后对新请求生效，进行中的分析不被静默切换。

## 7. P2 问题：核心流程稳定后的增强项

### P2-1：首次使用需要引导和环境诊断

项目目标用户不应依赖完整 README 才能完成首次配置。可在 P0/P1 稳定后提供向导：确认安全模式、配置模型供应商、测试连接、选择小型测试目录、分析一个视频并解释结果。环境诊断可覆盖视频解码、缩略图、存储空间、数据目录和连接状态。

**待验证**：新用户最常卡在连接配置、视频环境还是概念理解，需要通过真实用户走查确定向导顺序。

### P2-2：导出需要用途说明和结果验证

FCPX、ALE、XMP 和其他导出应显示目标软件或用途，而不只显示格式名。导出前提供字段映射与样本预览，导出后显示实际写出字段数、输出位置和失败项。此项依赖前面的标签、整理方案和批次记录稳定。

**待验证**：目标用户实际使用的剪辑软件、导入验证方式和最需要的字段集合。

### P2-3：素材预览可以发展为连续审片能力

应用内素材预览已有播放、进度、音量、倍速和定位文件等基础方向。后续可考虑上一个/下一个素材、连续浏览、保留/待定/淘汰标记、关键时间点和缩略图取帧，但这些功能应服务于整理批次，不应先做成孤立播放器。

**待验证**：用户是否把审片标记纳入整理方案，以及连续浏览对 100 个视频批次的实际价值。

### P2-4：大素材库需要保存视图和任务导向视图

在真实规模验证后，可增加最近导入、分析失败、待复核、重复素材等智能视图，保存筛选与排序，持续显示结果总数和查询条件，并允许长时间扫描或筛选取消。批量目标数仍必须以操作目标集为准，不能用当前加载页数量替代。

**待验证**：目标规模、分页方式和查询耗时是否已成为真实用户的主要阻塞。

### P2-5：逐步增加本地历史和变更审计

配置备份和部分重命名回滚不足以覆盖标签库修改、人工编辑、XMP、移动和导出的历史。可在批次中心稳定后逐步记录批次 ID、目标集、动作、结果、错误、标签库变更前后值和配置版本；恢复前检查文件是否已被外部修改。

**待验证**：单用户场景需要多细的历史粒度，以及哪些动作必须支持逐项恢复。

## 8. 本轮不建议做什么

为避免报告被误读成无限需求清单，本轮不建议优先投入以下事项：

- 不优先增加人脸识别、多语言标签、更多 AI 分析字段或更多低频 AI 入口；先让现有分类、摘要、标签和待审词流程可审阅、可追溯。
- 不把冷启动 AI 分簇重新列为在线能力；当前决策是规则分簇加人工终审草案，冷启动 AI 分簇停用。
- 不把所有长任务强行套用分析任务的三层重试和双进度；该决策只适用于分析任务，其他长任务应另行定义产品语义。
- 不以增加独立选择列、框选或另一套勾选集合解决批量操作；应坚持列表选中优先、无选中时当前可见列表全部的操作目标集规则。
- 不先做视觉装饰、复杂看板或常驻热力图；标签使用统计和审片增强应保持次要入口。
- 不把具体线程、数据库表、API 调用或文件锁实现写成主要产品建议；本报告关注用户可见的范围、风险、状态、结果和验收。
- 不在没有真实用户或桌面端证据时承诺最终性能、恢复完整性或所有导出格式兼容性。

## 9. 建议的信息架构

保留工作台、素材库、标签库和系统设置四个一级入口，但让各自职责和主动作更加明确。

### 工作台：处理当前工作范围

顶部固定显示工作范围、操作目标集和当前阶段。主动作随阶段变化：

- 发现：设定或累加工作范围、扫描、筛选。
- 分析：开始分析、强制重新分析、取消分析。
- 审核：查看待复核、接受或编辑结果。
- 整理：生成整理方案、模拟预览、批次确认和执行。
- 输出：导出、同步 XMP、查看批次结果。

低频动作进入“更多”，不与主流程动作使用相同视觉权重。

### 素材库：检索全部已入库素材

重点是搜索、高级筛选、保存视图、查看详情和累加到工作范围。取消入库属于管理动作，需保留清晰语义并降低与工作范围操作的混淆。

### 标签库：维护受控词表并处理待审词

默认突出待审词审核和标准词维护；标签组管理、近义巡检和标签使用统计作为可达但次要的工作视图。每次批准、移动、挂别名或丢弃前显示影响范围。

### 系统设置：管理连接、分析、安全、界面和导出

顶部显示当前生效配置和诊断状态；安全副作用、模型路由和重试设置优先于低频 Prompt 或导出字段设置。

## 10. 推荐产品路线

### 第一阶段：建立可信与安全基线

- 固定并展示操作目标集摘要。
- 明确只读分析、XMP、重命名和物理移动的副作用。
- 统一模拟预览、批次确认、执行结果和恢复边界。
- 处理自动 XMP 状态、旧列宽索引和文件名列宽异常等设置一致性风险。

### 第二阶段：统一整理方案与批次中心

- 生成按文件和按操作类型可审阅的整理方案。
- 支持排除文件、排除操作类型和保留人工修改。
- 批次确认后执行，记录成功、失败、跳过和冲突。
- 将分析已有双进度、重试、补跑和取消结果纳入任务中心。

### 第三阶段：增强 AI 可解释性与标签运营

- 记录模型、Prompt、标签库版本、归一来源和人工修改痕迹。
- 建立待复核筛选和待审词连续审核队列。
- 使用搜索型标准词选择器，降低自由文本和隐性拖拽负担。
- 继续坚持标签 AI 建议须人工确认，近义巡检保持次要入口。

### 第四阶段：提升长期使用效率

- 保存工作集和智能视图。
- 连续审片、快捷键和导出结果验证。
- 根据真实素材规模补充查询、扫描和批次历史能力。

## 11. 验收指标与验证方式

### 11.1 核心任务完成

- 新用户在不阅读完整 README 的情况下，能够完成“配置连接 → 处理 3 个视频 → 查看结果 → 生成整理方案 → 排除 1 个文件 → 执行剩余文件”。此项需真实用户或桌面端到端验证。
- 用户在任何批量动作前都能说出操作目标集、处理条数和工作范围边界。
- 用户在任何写盘动作前都能说出会修改什么、是否生成 XMP、是否可恢复。

### 11.2 结果可理解

- 首次出现工作范围、素材库、操作目标集、整理方案、模拟预览、批次确认和批次回滚时，都有简短解释。
- 完成记录同时显示成功、失败、跳过、取消和冲突数量。
- AI 结果能追溯到模型供应商、模型、Prompt 版本、标签库版本和人工修改。
- 用户能区分分析任务、整理执行和导出任务。

### 11.3 安全与恢复

- 默认分析不修改原视频，不自动生成 XMP；若产品最终默认不同，必须在首次使用和操作附近明确说明。
- 移动和重命名执行前可以查看完整源路径→目标路径差异。
- 不具备完整恢复能力的动作不宣传为完全可回滚。
- 取消、关闭应用、网络中断或部分失败后，用户能知道哪些已完成、哪些未完成、哪些仍可恢复。

### 11.4 效率

- 常用筛选和批量目标确认不要求用户逐条勾选。
- 待审词审核可以连续处理，批量 AI 建议只对用户明确选中的项目应用。
- 重试失败项不要求默认重跑整批。
- 高频工作范围可以保存并再次打开，但保存的工作范围不应被误称为素材批次。

## 12. 需要真实用户或桌面端验证的假设

以下问题不能仅靠静态材料定论，建议在整理方案原型完成后用 5–8 名目标用户进行任务走查：

1. 用户是否理解工作台只处理工作范围，而素材库浏览全部已入库素材。
2. 用户是否理解无列表选中时“当前可见列表全部”的目标集边界。
3. 用户是否能区分素材预览和模拟预览。
4. 用户是否能理解分析完成不等于文件已经整理完成。
5. 用户是否愿意在一份整理方案中一次审核多个动作，并能找到排除入口。
6. 待审词用户更偏好逐条审核、分组审核还是按 AI 建议批量审核。
7. 用户是否理解强制重新分析会覆盖分类、摘要和标签中的人工修改。
8. 对 100 个视频的素材批次，用户最希望优先看到缩略图、分类、标签、摘要还是风险提示。
9. 自动 XMP、物理移动、重命名和恢复边界的文案是否足以支持安全决策。
10. 当前本机设置中的自动 XMP 状态和旧列宽/文件名列宽异常是否会在真实操作中造成误解。

## 13. 配置一致性与发布风险提醒

以下风险应在面向真实素材的演示或交付前单独确认：

- **自动 XMP 状态**：项目材料强调 XMP 是写盘副作用；本机设置又存在自动 XMP 状态需要确认的情况。产品应确认这是用户有意配置，还是需要恢复为更安全的默认，并在界面中展示当前生效状态。
- **旧列宽索引和文件名列宽异常**：设置记录存在旧列索引，且文件名列可能出现异常宽度。应提供用户可见的“恢复默认布局”或迁移处理，不能要求用户手动编辑配置。
- **设置、文档和实际行为一致性**：自动 XMP、导出、回滚和批次记录的描述必须与实际可验证行为一致；无法通过静态材料确认的部分应标记为待验证。
- **敏感连接信息**：对外分享、截图、打包或提交前，应确保 API Key、服务地址和私人配置已脱敏；本报告不复述这些值。

## 14. 最终建议

下一轮产品目标应从“让 AI 自动完成更多整理动作”收敛为：

> **让用户快速生成一份可信的整理方案，清楚审核每项变更，安全执行，并在事后知道发生了什么。**

执行顺序建议固定为：

1. 统一整理方案与批次中心。
2. 显式呈现操作目标集和安全状态。
3. 统一 XMP、物理移动、重命名和回滚的准确语义。
4. 补足执行结果、任务历史和恢复边界。
5. 让 AI 结果可追溯、可审阅，并保留人工修改痕迹。
6. 降低待审词审核、标准词维护和设置中心的认知负担。
7. 最后扩展低频 AI、连续审片和视觉增强。

项目的方向和领域边界已经成立。能否从“可演示工具”走向“可放心使用的工具”，取决于每次批量处理是否都有清晰的工作范围、明确的操作目标集、可理解的整理方案、准确的副作用提示、可见的执行结果和诚实的恢复边界。
