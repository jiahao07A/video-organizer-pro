# rc6 分析失败处理：人工验收

此清单对应本轮6项UI/UX修复，也覆盖范围选择、分页及一次成功重试。自动化已验证核心行为；下面用于确认你在真实桌面上的操作体验。

## 先启动独立验收环境

本机已准备 `.release-build/rc6-analysis-failure-acceptance/`。它与正式安装目录、真实素材库分开，内含105条合成素材记录、104条未解决失败，配置仅指向 `127.0.0.1:18765` 本地模拟服务。模拟服务不转发外网请求，不消耗AI额度。此目录仅用于本机验收，不是正式发布包。

1. 先正常关闭其他版本程序，避免应用单实例限制。
2. 在 PowerShell 7 中运行下面命令。启动脚本会在后台开启模拟服务，再打开验收程序：

   ```powershell
   rtk proxy pwsh.exe -NoProfile -ExecutionPolicy Bypass -File "D:\Editing\视频素材\脚本\.release-build\rc6-analysis-failure-acceptance\开始验收.ps1"
   ```

3. 确认版本为 `0.0.1-rc6`。打开素材库，应看到 `page-001.mp4` 等合成素材。不要在验收环境中打开或切换到你的真实数据目录。
4. 测试中需要修改诊断模型时：先关闭失败处理窗口，再进入“系统设置 → AI 引擎 → 任务模型路由（跨供应商）”，找到“错误诊断”，供应商保留“本地模拟验收（不连接外网）”，只修改模型名，点击“保存所有设置”。不要点击连接测试按钮，以免影响请求计数。

本地模型含义：

| 模型名 | 模拟行为 |
|---|---|
| `diag-good` | 正常诊断，建议并发1、间隔2秒 |
| `diag-empty` | 返回空对象，用于验证诊断失败及不缓存 |
| `diag-invalid` | 返回正常诊断，但建议并发999，用于验证建议校验 |
| `diag-slow` | 等待8秒后返回正常诊断，用于验证取消提示 |
| `video-fail` | 等待8秒后返回503，用于验证重试取消与旧结果保留 |
| `video-ok` | 返回成功分析结果，用于验证解除失败 |

## 建议按顺序操作

### 1. 范围、分页和列表阅读

素材库打开“分析失败处理”，勾选“切换到全部素材库”。默认未解决应为104条，高级筛选默认折叠，能翻到第2页。

把操作范围改为“选中项”，选中1条，范围应显示1条；翻页后选中变为0条，但操作范围仍是“选中项”，不会自动变成全部104条。此时点击手动重试应提示没有目标，不应打开104条的预览。

明确选择“全部筛选结果”后才会处理跨页全部目标。单选素材后“查看详情”可点；悬停被截断的文件名、错误等，应看到完整提示。

### 2. 结束日期包含当天，错误日期能提示

在关键词中输入 `date-`，点击刷新，应有3条。展开高级筛选，开始与结束时间都填 `2026-11-09`，点击刷新。

**通过标准：**只剩 `date-early.mp4` 和 `date-late.mp4` 两条，`date-next.mp4` 不出现。开始与结束按UTC解释；中国时间比UTC快8小时。

再把结束时间改为 `2026-02-30`，刷新；应提示日期无效，仍保留原来2条结果。把开始时间填成 `2026-11-10`、结束填 `2026-11-09`，也应提示范围无效。测试完清空时间、关键词并刷新。

### 3. 非400恢复文案与400事实分开

状态选择“已恢复”，关键词输入 `recovered-non400`，刷新并查看详情。

**通过标准：**列表显示“已恢复”；详情显示“曾遇到400：否”，不会显示“曾遇到400，已恢复”。这条记录是合成503恢复记录。

### 4. 本地判断依据和历史错误全文

状态改回“未解决”，关键词输入 `history-long`，刷新，单选并点击“查看详情”。

**通过标准：**上方能看到发生阶段、原因分类“服务不可用”、本地判断依据、处理建议和400历史。下方选中历史记录后，全文阅读区显示以“合成历史长错误”开头的长文本；可滚动到末尾，可选中并按 Ctrl+C 复制。长文本不应把关闭按钮挤出窗口。

### 5. 空诊断计为失败，重复诊断会重新请求

把错误诊断模型设为 `diag-empty`。重新打开失败中心，筛选 `history-long`，操作范围选“选中项”，选中该素材，点击“AI诊断相同错误组”，确认预览。

**通过标准：**结果显示成功0组、失败1组。点击“仅重试诊断失败组”，再次确认预览，仍应显示失败1组。

可在浏览器打开 `http://127.0.0.1:18765/stats` 核对：`diag-empty` 的请求计数应比本项开始前增加2，证明空诊断没有变成可复用成功缓存。

### 6. 无效建议不关闭诊断结果

把错误诊断模型设为 `diag-invalid`，对 `history-long` 再诊断。

**通过标准：**诊断本身成功；点击该组“应用建议到重试设置”，提示并发必须为1～32。关闭提示后，原诊断结果窗口仍在，可继续阅读，不会启动视频分析。

如需检查正常流程，改用 `diag-good` 再诊断：应用建议应进入重试设置，并发填1、间隔2秒。此时点“取消”即可，不应发送视频分析请求。结果窗口的“重新诊断本次目标（忽略缓存）”应再次显示请求预览，取消预览不应请求。

### 7. 取消提示不被刷新、翻页或筛选覆盖

视频主分析默认使用 `video-fail`。在失败中心清空关键词，保持104条未解决，操作范围选“选中项”，选中几条素材后手动重试。本次并发设1，保持请求预算2，在预览中确认目标数量后启动。

等开始请求后点击“取消本轮重试”，立即点击刷新、翻页或切换原因筛选。

**通过标准：**取消按钮显示“正在取消”且不可重复点；任务状态始终保留“等待当前请求完成”，列表统计仍可更新。当前请求结束后显示本轮结果，不再提交后续请求。成功、仍失败、跳过、取消分别计数。

注意：8秒从服务器收到请求起计算；视频抽帧和初始化也需要时间。已经发出的请求允许结束，取消不代表立即中断网络连接。可通过 `/stats` 核对 `video-fail` 计数不再持续增加。若对 `history-long` 重试失败，原摘要“验收旧摘要（重试失败应保留）”应保留。

诊断取消可改用 `diag-slow`，请求开始后取消诊断，再刷新筛选，提示也应保持。关闭窗口会先请求取消，待当前请求结束后才能关闭。

### 8. 成功后移出未解决列表，历史保留

最后再测成功，避免提前改变上面需要使用的失败样本。先在系统设置把“视频主分析”模型改成 `video-ok` 并保存。筛选 `history-long`，只选这一条手动重试，模式选“仅主API”，确认目标1条后开始。

**通过标准：**本轮成功1条，该素材移出未解决列表；切换到“已恢复”还能找到它，详情历史仍在，400标记仍为否，摘要变成“本地验收重试成功”。

## 入库编号回归

使用新建的独立测试数据目录和素材副本：导入40条，等待缩略图完成，分析这40条、重命名、回滚，再累加另外40条。应共有80条，编号为1–80，前40条编号保持不变。重复浏览同批素材不新增记录、不额外消耗编号。

入库编号是固定身份，不是素材数量；取消入库或旧版本可能留下空号，旧库不自动重编号。此次真实库只读统计120条，编号为1–40、121–160、201–240，无重复路径。工作台80条是当前范围，素材库120条是全部库存；二者范围不同。新版本保留已有编号和历史，只阻止更新继续消耗编号。

## 真实工作流反馈回归（2026-11-09）

以下步骤应使用包含本轮修复的新构建。既有rc6安装包不会因源码修复自动变化。先备份数据库和素材，重命名仅使用素材副本。

1. 从工作台打开失败中心，重试一条能成功的素材。结束后关闭失败窗口，主列表的分类、标签和状态应与右侧详情一致，无需重启或重新选择目录。再从素材详情入口重复检查。
2. 勾选“曾遇到400”，状态应自动切换为“全部历史”，已恢复记录也能显示。随后可手动改为“未解决”求交集；如果结果为空，应先检查当前操作范围，需要时明确切换全库。此次真实库只读快照中有3条明确400历史，均已恢复；不能把其他恢复记录猜成400。
3. 主列表应显示“已分析”“已重命名”等中文状态；普通失败恢复只显示“已恢复”。重分析仍失败且有旧结果时显示“保留旧结果 / …”，不会附加无依据的400说明。
4. 通过多选文件设定工作范围，执行重命名。完成后文件数和分类标签应保留，路径更新为新文件名；回滚后仍保留列表，路径恢复。再用文件夹范围重复检查。
5. 分别使用40、200、1400个素材副本，单独记录打开预览和执行耗时。执行时应显示已处理/总数进度，1400条范围查询不得报表达式深度错误。不同磁盘、杀毒软件和侧车文件会影响时间，勿将合成空文件基准当成真实素材性能承诺。

本机合成素材基准：40条约4.723秒降至0.377秒，200条约7.826秒降至1.551秒，1400条约49秒降至10.541秒；修复后范围分别保留40/200/1400条。1400条旧实现完成重命名后，范围查询另报SQLite表达式深度错误。新实现预览分别约0.033/0.046/0.254秒。真实素材、真实供应商和新版安装包仍须人工复测。
