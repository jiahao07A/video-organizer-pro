# 视频分析结果校验与重命名保护

Status: proposed

Date: 2026-11-13

Issue: #73

## 背景

合法 JSON 不代表完成了有效的视频分析。旧实现将“抽帧失败，未能获取视频画面内容”等失败说明保存为摘要，计为成功并用于文件名。真实诊断记录中的本地抽帧成功，不能把模型的失败说明归类为素材解码损坏。

## 决定

视频业务层提供统一的结果契约，复用 Pydantic 的严格字段与容器校验，必要字段为非空分类和摘要。现有动态单选字符串、多选列表、空组及未配置标签组的响应继续兼容；新增字段保留，不放宽原有标签归一策略。

既有动态组可与 success、ok、status、error 等协议字段同名。已配置的同名字段按标签结构校验，其他字段继续按协议语义判断；新响应、缓存和业务复核使用同一配置。历史重命名使用已保存的归一组身份消除歧义，避免组配置删除后误判旧成果；失败性摘要仍独立拦截。

通用网关允许业务方传入结果校验器，在记录请求成功、恢复成功和指标前运行。仅视频主分析传入该校验器，其他任务及音频不改变契约。明确的模型失败标志、模型自述无法分析图片及无效字段结构按响应问题处理，沿用原有调用层、单条层、批次补跑的有界重试；手动恢复及 HTTP400 后恢复继续受共用预算约束。错误使用固定说明，异常与诊断不复制原始响应或图片。

持久缓存与恢复上下文复用同一契约。无效缓存按精确键移除并重新请求；无效结果不得进入归一、待审标签、成功事务及文件副作用。正常结果仍按现有连接、模型、任务、提示词与词表边界缓存。

旧素材库不在启动时自动扫描改写，不新增数据库迁移，也不自动发出收费请求。重命名在使用摘要、分类或标签时拦截明确失败的旧分析结果和未修正的失败项，逐条报告，其他素材继续处理。预览显示不可执行原因，监控进入待核对。仅原名、日期的命名不受分析失败限制；人工修正后的字段优先于历史原始响应。规则生成空文件名时拒绝执行，避免仅保留扩展名。

规则显式包含原扩展名、或正则去除主体时，也须校验主体非空。监控及异步改名 Worker 的调用与报告快照使用既有文件操作锁的同一临界区，防止其他线程覆盖共享报告而把失败误记成功。

## 验收与限制

使用真实临时数据库、文件和模拟远程客户端进行响应、缓存、重试、失败中心、重命名、GUI、监控及并发回归，并补充真实 OpenCV 抽帧到文件重命名的端到端测试。正常画面描述中出现“失败”不应被泛化关键词拒绝。

失败短语也可能是画面中错误提示的主语，因此明确的“错误提示显示在屏幕上”后续语法按画面描述处理；第一人称、抱歉等模型自述仍按失败判断，不因其他位置提到屏幕而放行。

这是明确失败检测和结构防线，不能识别所有模型幻觉，也不能证明上游实际视觉能力。更换供应商或模型后，用户可选择异常素材执行强制重新分析；不自动修改已改名的真实文件。

本决定补充 ADR-0005、ADR-0011 和 ADR-0012，保持既有重试预算、保留旧成果和原子标签副作用边界。源码回退即可撤销逻辑，无数据库结构回滚。
