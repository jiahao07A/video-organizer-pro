# 设置与标签配置的独立格式版本及无损升级

Status: accepted

Date: 2026-11-21

Issue: #85

## 背景

设置中心需要安全读取旧连接、模型、监控和标签配置。仅在内存补字段会反复迁移；按字符串比较版本、丢弃扩展字段，以及读取失败返回默认值，可能导致配置被后续自动保存覆盖。

## 决定

设置和标签 JSON 使用独立整数 `config_schema_version`，当前为 1。加载与保存入口集中使用 `core/config_compatibility.py`，先检查未来格式，再进行确定的兼容转换和缺失补齐，保留扩展字段及显式继承。标签原有业务版本继续使用语义化版本比较。

只针对这些不涉及数据库的配置适配，允许普通加载时自动升级，但必须先完成可校验的源字节快照，再原子替换。快照按源内容摘要命名，以支持幂等和失败重试。损坏结构、不支持的版本或备份失败必须阻止覆盖，不得默默改为默认配置。标签导入的数据库恢复记录继续按原协议恢复投影，但也保留源文件并拒绝未来版本。

本决定补充 ADR-0008：其数据库迁移、目录搬迁、旧成果导入的用户确认门禁不变。本轮自动升级仅限配置文件的兼容补齐和已知历史结构适配，不自动执行上述管理数据操作。设置与标签分别升级，不提供跨文件或跨进程事务。

## 后果

旧配置首次升级需要目录及备份目录可写，否则报告失败并保留原文件。以后读取已适配文件不重复写入。原始快照包含原配置中的凭据，需同样保密。还原旧格式后可重新适配；禁止通过修改版本标记绕过未来版本保护。用户恢复说明见 `docs/configuration-upgrades.md`。
