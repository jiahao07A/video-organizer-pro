# 便携数据目录与受控一次性升级

Status: accepted

Date: 2026-10-11

Issue: [#7](https://github.com/jiahao07A/video-organizer-pro/issues/7)

## 背景与决定

当前数据库、结果文件、缩略图和备份使用相对路径，而设置与标签配置使用项目/可执行文件位置。不同启动工作目录可能打开不同数据，管理数据也难以整体搬迁。

默认使用程序旁的 `data/` 统一管理数据库、设置、标签配置、缩略图与备份，支持用户自选位置；默认位置不可写时提示另选，禁止静默切到用户目录或新建空库。路径定位以项目/可执行文件位置为依据，不依赖进程工作目录。定位用户自选目录的启动记录只保存必要路径、格式版本及“数据库是否已完成首次初始化”状态，不形成第二份业务配置。新选空目录与尚待旧 JSON 确认导入的迁移目录可明确标记为待初始化；数据库创建成功后更新状态。已标记初始化完成的目录缺少数据库时必须报错，不能静默新建空库。

首次升级、旧 JSON 首次导入与目录搬迁统一走“检查来源 → 提示确认 → 可靠备份 → 转换/复制 → 验证 → 激活 → 记录完成”的可恢复协议。升级过程中暂停相关管理数据操作，窗口保持响应；普通启动只读取轻量版本状态，不重复升级和全库校验。已有有效数据库时以其为准，不自动合并旧 JSON；损坏数据库必须报错，不能静默视为空库。

## 取舍

- 默认 Windows 用户目录：未选，用户明确要求程序旁的便携布局；以可自选目录和明确权限提示处理受保护安装位置。
- 启动时自动合并全部旧文件：否决，来源不清且可能恢复用户已取消入库的记录。
- 为了 2 秒启动显示空窗口后继续放任数据升级：否决，首批结果和写入边界同样属于就绪标准；首次升级单独计时并明确提示。

## 后果

数据目录内部资源引用需相对数据根解析，搬迁成功前不切换活动目录，并保留源数据供恢复。目标已有有效库时不得隐式覆盖或合并。原始视频保持原路径，本轮不提供跨电脑原始视频路径重定位。

普通启动从进程启动计时，包含模块导入、初始化和首批素材结果；首次升级的处理耗时另行报告。遇到不支持的更新数据版本拒绝写入。上述是待实现方向，不代表数据已经搬迁或 2 秒目标已经达到。
