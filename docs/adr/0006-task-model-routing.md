# 任务模型路由：按 AI 功能跨供应商选模型

Status: accepted

Date: 2026-07-22

## Context

产品已支持最多五个**模型供应商**档案，但原先约定「任意时刻只有一个**当前供应商**」，分析与标签库 AI 整套共用。用户需要用贵模型做视频分析、用便宜模型做词表运营，且不同标签库 AI 功能调用次数与上下文长度差异大。

## Decision

1. **模型供应商**只承载连接身份：显示名、API Key、API Base URL（最多五个）。
2. **任务模型路由**为每个 AI 功能单独指定「供应商档案 + 模型名」。固定六槽：视频分类、标签生成、内容描述、待审词 AI（含批量待审 AI 分拣）、近义巡检、标准词 AI 助手。
3. **当前供应商**降为**默认回退**：某功能未单独配置供应商时，使用当前供应商的 Key/URL；模型名按该功能路由或档案缺省。
4. 冷启动 AI 分簇产品停用，**不占**路由槽。
5. 同一次分析任务内不同子调用可解析到不同供应商；切换路由或当前供应商不中断进行中的本轮请求，对新请求生效。

## Considered options

- 仅档案内换模型名、禁止跨供应商（否决：不满足跨中转/跨价位）。
- 仅「分析一套 + 标签库一套」两槽（否决：标签库三类成本差大，粒度不够）。
- 无限自定义任务槽（否决：设置与测试爆炸）。

## Consequences

- 旧「当前供应商 = 全部 AI 唯一连接」语义废止；迁移时把原档案内三模型写入对应分析三槽，标签库三槽默认回退当前供应商。
- 设置 UI 需提供路由表；解析逻辑须可单测且为 AI 调用唯一真相来源。
- 与 ADR-0004 正交：路由只决定「打哪、用哪模」，不改变「建议须确认才写库」。
