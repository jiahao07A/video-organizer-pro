# 按数据类型确定单一持久来源，结果文件仅显式导出

Status: accepted

Date: 2026-10-11

Issue: [#7](https://github.com/jiahao07A/video-organizer-pro/issues/7)

## 背景与决定

现有结果 JSON 每次启动自动回灌 SQLite，分析完成又全库重写 JSON/CSV；设置与标准词也存在可编辑双份数据。这同时增加日常读写与启动成本，并存在过期副本覆盖修改、重新导入已取消入库记录的风险。

保留 SQLite 和现有配置文件形式，按数据类型明确唯一权威来源：素材记录、入库编号、标准词、别名、待审词和历史记录以 SQLite 为准；用户设置以数据目录内设置文件为准；标签组定义、组规则、提示词和导出规则以标签配置文件为准，其中词列表只允许由数据库生成兼容投影。历史数据库设置副本只在明确的首次升级/恢复中作为输入，普通运行不再覆盖设置文件。

JSON/CSV 分析结果改为显式导出，不作为自动恢复或同步源；已有有效数据库时不自动合并旧结果 JSON。备份使用独立的一致性快照与恢复协议。单条保存和分析收尾不得依赖全库加载/重写。

## 取舍

- 保留多份可编辑主数据并在启动时合并：否决，增加线性成本和无法可靠判断新旧的冲突。
- 将所有配置立即迁入新的数据库结构：本轮不采用，统一目录与消除双源不要求同时重写所有配置形式；保留现有配置形式可减少无关兼容变化。
- 只把旧 JSON 导入放到后台：否决，仍会重复工作，且窗口显示后旧数据可能覆盖新编辑。

## 后果

首次切换设置来源必须先保留按旧规则实际生效的配置，避免数据库副本中的更新丢失。标签配置与标准词数据库差异必须报告，不能通过静默添词/改组来掩盖冲突。跨配置文件与数据库的组合操作需要可恢复协议，不能声称由单次 SQLite 事务覆盖多个文件。

本决策是确认的设计方向，尚未实现。升级流程必须保留源快照；用户主动导入仍需显示来源、范围与冲突。现有工作范围、操作目标集、标签人工确认与模型路由决策不变。
