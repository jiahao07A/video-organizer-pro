# 分析失败处理中心与统一手动重试

Status: accepted

Date: 2026-11-08

Issue: #65

## 决定

在ADR-0011的400恢复基础上增加统一失败索引。普通分析失败也进入独立记录，但失败分类与恢复状态分开保存；只有用户主动操作才会触发诊断或手动重试。旧400策略、自动调度和标签库AI保持原有边界。

失败索引保存规范化类别、阶段、HTTP状态码、连接摘要、错误特征、400历史和是否保留旧结果，并提供数据库组合筛选、统计与分页。旧数据库升级时只从明确错误文本补录，不根据文件名或孤立数字猜测。

手动重试冻结目标集合，支持有效策略、仅主API和指定API；本次并发与间隔作为临时设置，预算仍由恢复策略控制。不存在或不可读取的文件在预览阶段跳过；取消停止新提交。成功结果、标签计数和待审词继续在同一事务完成。

错误诊断是独立的`error_diagnosis`任务路由。按规范化错误分组，每组一次请求并缓存；仅发送脱敏技术信息。AI建议只用于填充经校验的临时重试参数，不能直接发起请求。

诊断缓存与新响应使用相同的必要字段校验；不完整诊断不作为成功结果复用。用户可主动忽略缓存重新诊断，或仅处理诊断失败组，仍需确认请求预览。建议校验失败时保留原诊断窗口。

统一窗口的恢复状态使用通用文案，400历史作为独立事实；本地依据及历史错误提供可滚动、可复制的全文阅读。列表统计与运行状态独立。时间查询按UTC解析日期及无时区时间，带时区输入按实际时刻比较；结束日期使用次日零点的排他边界。

## 影响与回滚

数据库版本从2升级到3。启动升级继续要求确认、完整备份及事务迁移；单独使用DatabaseManager时也在升级前保存一致性快照。版本3完整性检查要求失败索引及诊断缓存表存在。旧普通失败按已有错误补录，未知请求次数和供应商保持空值。原400入口与筛选继续限定曾遇到400的记录。

增加失败索引和诊断缓存表、相应索引及离屏测试。请求数量和费用由手动预算、诊断分组和预览上限控制。回滚旧程序前必须恢复升级前数据库备份。
