# 分析任务：三层自动重试 + 双进度与行临时态

Status: accepted

Date: 2026-07-22

## Context

分析主路径存在瞬时 API/解析失败（如空 body、JSON 解析错误），仅靠客户端默认 `max_retries` 不足；用户对「卡在哪、哪条在跑、补跑算不算重来」感知不清。产品要求在**不扩大到重命名等其它长任务**的前提下，健全重试并提升进度准确性。

## Decision

### 范围

仅 **分析任务**（工作台「开始分析」/「强制重新分析」）。不在本 ADR 统一改造重命名、导出等 Worker。

### 三层重试（默认全自动）

| 层 | 语义 | 默认上限 |
| --- | --- | --- |
| 调用层重试 | 单次 AI 请求内对瞬时错误退避再试 | 额外 2 次（共 3 次尝试） |
| 单条层重试 | 单条视频整段流程失败后本轮再完整尝试 | 每条 2 次完整尝试 |
| 批次补跑 | 首轮结束后对仍失败集合自动再跑 | 1 轮；高级设置可关闭 |

可重试（瞬时）：超时、连接重置、HTTP 429/502/503、空 body、JSON 解析失败等。  
不可重试：401/403 等鉴权失败、文件不存在/无法打开、用户取消。

设置：默认采用上表；高级可调次数与「自动批次补跑」开关（默认开启）。

### 进度与行态

- **总进度**：覆盖整次分析任务；进入批次补跑时**不清零**。
- **子进度**：对应当前轮（首轮 / 补跑段）；补跑段**单独标注**，子进度从 0 再计。
- 首轮分母 = 分析目标集条数；单条层重试不增加分母；补跑分母 = 本轮失败集条数。
- 进度按**终态文件数**推进（成功或最终失败），不以发出请求数为准；并行时允许「进行中 N 条」文案。
- **分析行临时态**（分析中·阶段 / 重试中 / 成功 / 失败）仅 UI，**不写入**素材库持久 `status`。

### 取消分析

协作式：停止新提交与批次补跑；尽量不强制中断进行中请求；已成功落库保留；未完成可记取消原因。取消后不得自动再开批次补跑。

## Considered options

- 仅调用层重试、批次失败仅靠下次手动再分析（否决：体感仍脆，与「健全重试」不符）。
- 批次补跑须用户确认（否决：本轮明确选择全自动；用设置关闭满足控费）。
- 将 analyzing 写入库 status（否决：污染分析目标集与崩溃残留态）。
- 进度分母含全部预计尝试次数（否决：完成数与文件数错位，主指标改为终态文件数）。
- 统一长任务进度框架含重命名（否决：本轮 R1 收窄范围）。

## Consequences

- 需扩展分析任务回调（阶段、行 path、轮次、取消标志），并保证线程池下 UI 更新线程安全。
- 自动三层重试会增加 API 费用；默认上限与「可关 C」为必要控费手段。
- XMP 等副作用失败仍不得推翻已成功分析落库（与既有分析/侧车边界一致）。
- 实现后应有单测覆盖：可重试判定、次数上限、补跑仅一轮、取消不再 C、进度分母与双条语义。
