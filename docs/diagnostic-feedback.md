# 日志诊断与问题反馈

应用会在启动时自动记录详细日志。确定管理数据目录后，运行日志保存在其中的 `logs/`；此前的启动日志位于用户本地应用数据目录 `VideoOrganizerPro/diagnostics/`。写入失败时，主界面会提示，最近1000条事件暂存在内存中，可继续尝试导出。

日志包含操作阶段、线程、耗时、错误代码与代码栈位置，并用匿名编号关联会话、任务、素材和请求。API只记录技术摘要，不保存完整请求和响应。日志在写盘前脱敏，导出时再次检查。程序日志每文件10MB轮换，统一容量预算200MB，只逐个清理已知日志文件；你保存的诊断ZIP不会被自动清理。

本机匿名身份密钥保存在用户启动日志目录的 `identity.key`，用于让重启前后的同一素材仍能关联；密钥不会进入诊断包。导出时素材编号再转换为包内编号。若该目录无法写入，会退回本次进程的临时身份，跨启动关联可能不完整。

## 提交反馈

1. 点击左下角导出预设下方的“问题反馈 / 发布 Issue”。
2. 填写问题摘要、复现步骤、期望和实际结果，选择日志时间范围。
3. 点击“生成诊断包并打开 Issue”，选择ZIP保存位置，等待后台整理；生成中可以取消。
4. 查看窗口中的脱敏说明、缺项清单和反馈正文。ZIP中按report、environment、logs、analysis分类，可解压检查。
5. 将ZIP拖入已打开的GitHub页面附件区域；必要时点击“复制反馈正文”补充完整内容，检查后自行提交。

打开网页不代表已经提交。浏览器打不开或没有网络时，ZIP仍保存在所选位置；窗口提供仓库链接和正文，联网后可自行提交。单项采集失败不会阻止其他项目导出，缺项、损坏和容量裁剪会记录在 `report/manifest.json`。

默认收集本次及最近一次异常会话，也可选24小时或7天。失败历史保留最近最多200条当前失败技术摘要，24小时/7天按更新时间筛选。旧格式自由文本日志不原样打包。包内不包含素材、缩略图、数据库、原始配置、转录或分析正文。正文和日志超过容量时优先保留错误及近期事件；内容和ZIP各最多20MB。

原生崩溃记录属于尽力捕获，强制结束、断电或系统故障可能只留下异常退出线索。自动脱敏也无法替代发布前检查，手写反馈请避免填写账号、凭据和不必要的个人信息。
