# 并行处理设置

设置保存在“系统设置 → 分析与处理”。修改后保存，对下一次任务生效，正在运行的任务保持原配置。

| 设置 | 影响的任务 | 含义与建议 |
| --- | --- | --- |
| 同时分析的视频数 | 视频分析 | 同时处理的视频上限，包含准备图片、等待AI和整理结果。可设1～512，建议从8～16开始。512不代表每秒请求512次。 |
| 分析图片准备并行数 | 视频分析的前置抽帧 | 同时为多少条视频解码并准备AI图片。可设1～512，默认4；4K素材建议2～4。CPU和磁盘有余量时逐步调高，通常不必超过同时分析的视频数。 |
| 入库缩略图并行数 | 新素材入库 | 同时生成列表缩略图的数量。可设1～512，建议4～8。不会提高视频分析或标签库AI的请求并发。 |

分析流程为“准备图片 → 请求AI → 保存结果”。图片准备不够快时，即使有512条分析任务，也可能暂时只有少量请求到达API；请求日志还可能记录响应完成时间。因此应同时观察任务数、CPU/磁盘负载和API的在途请求数，不能仅按每秒日志条数判断并发是否生效。

开启“智能场景检测”会遍历解码视频、寻找场景后再选帧；关闭后按时间均匀抽帧，通常更快，但送给AI的画面会不同。程序不会为提高速度自动关闭它。

若512条任务的请求仍稀疏，先检查图片准备并行数和场景检测耗时，再检查供应商限流与响应时间。不要同时把所有选项设到最大：更多解码任务会争用CPU、磁盘和内存，可能反而变慢。

标签库“导入标签”中的AI分类会将标签列表交给分类请求，以上三个设置不控制该功能。导入确认后的数据库写入会在后台批量执行，并在写入前保留管理数据快照；如果出现保存失败，请按错误说明保留备份，不要将旧快照直接覆盖到已有新增数据的素材库。
