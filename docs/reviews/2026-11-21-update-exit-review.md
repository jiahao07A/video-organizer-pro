# RC12 更新退出交接复审与重打包

关联：Issue [#90](https://github.com/jiahao07A/video-organizer-pro/issues/90)、PR [#91](https://github.com/jiahao07A/video-organizer-pro/pull/91)。

## 复审结论

现场只读核对为RC10。其更新方法只关闭窗口，没有结束托盘事件循环；更新准备门禁又阻止再次退出。目标安装包不能改变已经运行的旧二进制，因此旧实例仍需先取消安装器，确认无写入任务后退出，再手动安装。

当前RC12源码的正常退出已有显式Qt quit，但失败恢复仍有缺口。两名独立审阅者按需求、规范分工，主审逐项检查差异、运行联合回归并复核真实安装证据；发现后补正，再次派发审阅，没有新增其他审查代理。

| 问题 | 修复与可检出证据 |
| --- | --- |
| 关闭拒绝或监控停止异常后永久禁用界面 | FAILED统一恢复准备/退出标志及界面；Qt关闭事件内部捕获异常。新增场景先失败后通过 |
| 连续停止失败后再次托盘退出隐藏窗口 | 更新退出与普通真正退出共享停止保护；真实QAction重试、QTest主题点击验证窗口可见可操作 |

## 隔离及适用边界

为不干扰用户仍在运行的RC10，出站测试客户端使用相同最终业务源码，测试hook只改变RC11版本身份、独立互斥量、按钮驱动和证据记录。真实备份、签名检查、准备任务、安装器启动、close及monitor.stop均未替换。入站payload是无hook的正式EXE，安装后真实执行。签名缓存预置，不能据此宣称已测公网下载。

测试安装器仅改变互斥量名称、两个资源绝对路径，并启用已有IsolatedSmoke分支隔离AppId、注册及快捷方式；自动差异审计确认安装`[Code]`逻辑与正式源码完全一致。所有测试安装器与身份包均禁止发布。全程只用合成数据及新建目录，未终止用户进程或修改真实素材库。

Windows10没有实机证据，不能宣称通过；最低要求仍为Windows10 1809/build17763 x64。既有Qt弃用警告保持可见，第三方驱动或分析调用永久阻塞未穷举。监控停止等待与安装器等待均不等于强制退出。
