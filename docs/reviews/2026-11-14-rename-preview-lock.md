# rc10 工作台重命名失败：Windows 预览占用修复

状态：源码修复及独立复审通过；按用户要求撤销未经授权的rc11升级，恢复rc10重新打包及隔离启动验证完成，待用户现场复测；未提交。

## 问题与根因

用户在本轮rc10安装包中从“工作台 → 应用重命名”触发失败。只读诊断日志确认，同一条素材两次在 `os.rename` 抛出WinError32，分别为北京时间2026-11-14 16:06:31和16:07:18。未修改用户数据库、设置、素材或运行进程。

在隔离环境中以真实QMediaPlayer加载合成MP4，调用真实工作台入口、RenameWorker、SQLite和文件系统，加载未播放、播放、暂停、停止四种状态均重命名失败。仅增加卸载预览源 `set_media(None)` 的对照即成功。`stop()`停止播放仍保留媒体源及文件句柄，应用自身预览因此阻止Windows重命名。

此前全项目审查分别覆盖了媒体播放和文件重命名，但未覆盖两者同时存在的组合，此为本轮测试缺口；此前测试通过不能据此证明这个场景可用。

## 修复

`WorkstationView.start_rename` 在用户最终确认且忙碌检查通过后，如果本次真实更名目标包含当前预览路径，则先卸载预览源，再启动既有RenameWorker。目标比较使用Windows路径大小写/斜杠等价规则。模拟、取消、忙碌拒绝和无关预览保持原状。不自动续播，用户可重新选择素材预览。没有更改服务层文件操作、冲突、补偿、数据库或范围规则。

唯一版本源保持 `0.0.1-rc10`。此前主Agent自行升级rc11未经用户允许，已按用户要求恢复；后续仅在用户明确授权时更改版本。保留AppId和数据协议。没有结束外部进程或强制解除其锁；外部真实Windows锁仍安全失败，文件、XMP、SQLite整行和工作范围保留，释放后同入口重试成功。
